# KyStudy v0.1.0 开发交接文档

本文档是面向后续开发 agent 的执行契约。目标是在不扩大产品范围的前提下，完善当前工作树已有功能，完成当前产品文档与 R1–R65 已承诺行为，最终准备 Windows 首版 `v0.1.0`。

## 1. 目标与不可变边界

### 1.1 最终交付目标

- 公开发布到 GitHub，供第三方安装使用。
- 首版只支持 Windows 10/11 x64。
- 版本号为 `v0.1.0`。
- 主交付为 Windows NSIS 安装包，同时提供 ZIP 便携版。
- 更新通过 GitHub Releases 手动完成，首版不实现自动更新。
- 许可证使用 GPL-3.0：允许商用，但分发包含修改版的程序时必须继续提供对应源码。

### 1.2 范围冻结

必须完善当前产品文档、M/R 文档和现有实现已经承诺的功能；不得新增用户场景、产品模块或新的默认入口。

允许的工作：

- 修复缺陷；
- 补齐已写入 PRD、ADR、M1–M13 或 R1–R48 的行为；
- 为既有功能增加必要的 UI、迁移、测试、错误处理、性能和发布工程；
- 重构实现，但不得改变已冻结的数据语义和用户可见契约。

禁止的工作：

- 新增云同步、团队协作、商业后台、多平台、自动更新、遥测等模块；
- 将 AI 变成核心流程前提；
- 删除历史数据、历史迁移或旧版兼容入口来“简化”实现；
- 在未完成当前链路验收前继续扩展下一条链路；
- 用新的历史验收文档覆盖或改写旧验收结果。

## 2. 开发顺序

严格按以下依赖顺序推进。每条链路完成后，先通过目标检查和一次交叉审查，再进入下一条。

1. 工作区、PDF 导入、OCR、题库索引和题目浏览；
2. 作答登记、组卷工作台和错题状态写入；
3. 错题方案、每日队列、连续复习与反馈；
4. 周期计划、月历、进度、顺延、跳过与撤销；
5. 资料搜索、AI 规划、错题解析和 Provider 管理；
6. 思维导图；
7. 设置、备份恢复、迁移兼容、错误诊断和整体 UI 收敛。

不得以“自动化测试通过”代替桌面验收。桌面验收由项目负责人执行，agent 负责准备构建、步骤、证据和问题记录。

## 3. 第一阶段：工作区、PDF、题库索引与浏览

### 3.1 工作区启动

- 首次启动自动创建默认本地工作区，不要求用户填写数据库位置、工作区名称或技术参数。
- 已有工作区必须直接打开，不能创建空库覆盖旧数据。
- 未来 schema、迁移失败、数据库损坏、外键/完整性检查失败时安全阻断，保留现场并提供重试、备份和诊断建议。
- 工作区状态页保留数据位置说明、备份入口和错误状态，但不向普通学习页面暴露绝对路径。

### 3.2 PDF 导入完成标准

必须准备并在本机验收以下样本：文本 PDF、扫描 PDF、混合 PDF、多科目 PDF、损坏/中断导入样本。真实版权资料不得提交到 GitHub；`fixtures/` 只放项目自生成、可公开的小样本。

- 文本 PDF：自动建立可浏览题目索引。
- 扫描 PDF：导入成功但进入 OCR/人工索引流程，不能伪装为已完成。
- 混合 PDF：逐段显示状态，成功部分可用，失败部分可单独重试。
- 多科目 PDF：先生成待确认分段，用户为每段选择科目和练习册后才写正式索引。
- 任一索引失败：原始资料、已成功分段和分析草稿保留，不要求重新导入。
- `pending / 0` 分段必须可见，但不得进入题目浏览、拼卷和错题候选。

### 3.3 索引置信度

- 高置信度：允许自动预选，但必须标明“自动识别”。
- 中/低置信度：标记“待人工确认”，禁止进入正式题库和每日队列。
- 归类不完整、分段冲突、重复活动范围：阻止提交，仅保留草稿。
- 用户修正优先于自动识别，并在重开窗口后保留。
- 题号缺漏、非纯数字题号、OCR 异常只产生诊断提示，不自动补题、删除题目或修改用户数据。

### 3.4 OCR 交付

- OCR 是可选的受控本地 sidecar，不进入最小主安装包。
- GitHub Release 提供独立 OCR 组件包；应用内提供本地安装、完整性校验、版本显示、修复和移除。
- 模型随组件提供，识别时不联网下载。
- 无 OCR 时，文本 PDF 和人工索引仍可用；扫描页明确提示安装组件或人工处理。
- OCR 逐页串行、可取消；取消、崩溃、缺失或结果非法不得破坏原 PDF 和正式索引。
- OCR 结果最多作为低置信度候选，必须人工确认。

### 3.5 大资料与恢复

- 分析显示当前页、总页数、OCR 页数和候选题数量。
- 分段正式写入必须原子提交；某段失败不影响已成功段。
- 应用重启后保留已完成、pending 和失败状态。
- 至少用约 1000–1300 题真实 PDF 做本机压力验收，并记录耗时、取消和峰值内存；不要先承诺固定秒数。

### 3.6 题目浏览完成门槛

- 每道正式题至少有一个有效 PDF 区域；页码、坐标、顺序均经过校验。
- 点击题目可直接定位正确页和区域；多区域题按稳定顺序展示。
- 跨页、矩阵/行列式等复杂区域可手动移动、缩放、增加和移除。
- 人工调整区域后重新索引不得覆盖。
- 相对补题必须原子保存；保存失败、取消或重复操作不得留下半条题目或错误顺序。
- 关闭并重启后题号、区域、分类和当前浏览范围一致。
- 回收的分段/题目不出现在正常浏览和拼卷中，但按既定规则可恢复。

## 4. 第二阶段：作答登记与组卷

### 4.1 批量作答登记

- 历史记录不可变，当前状态取最近一次结果。
- 用户输入完成范围、做错题号和不全对题号；其余完成题自动记为做对。
- 提交前展示完成总数、三种结果数量和日期。
- 错题号必须属于当前范围；重复题号、非法范围、缺失索引和跨册歧义必须阻断。
- 做错与不全对不得重叠。
- 一次提交原子完成，防重复点击，并具备幂等重试能力。
- 成功后提供短时整批撤销；撤销恢复此前状态，不删除更早历史。
- 可补录过去日期，禁止未来日期，按用户本地时区记录。

题号输入只支持纯数字范围（如 `1-20,25`）和非数字题号的精确匹配；不实现通用表达式或隐式猜测。

### 4.2 组卷范围语义

首版允许适度高自由度，但限制复杂度：最多 5 个范围组。

- 组内条件取交集：科目、练习册、PDF 分段、章节、篇章、题型、作答状态、题号范围。
- 多个范围组取并集。
- 排除题目优先于包含。
- 按题目 ID 去重。
- 章节始终隶属于具体书籍；同名章节不跨书合并。
- 失效的书籍、章节或分段条件必须提示并修复后才能生成。
- 首版不支持通用查询语言、逐题强制加入、范围组最低/最高配额和复杂模板。

### 4.3 组卷 UI

实现独立的大尺寸组卷工作台，采用“选择范围 → 设置规则 → 预览生成”三步流程，可来回编辑且状态不丢失。

- 左侧科目/书籍/分段/章节树支持批量勾选。
- 右侧显示最多 5 个范围组、实时题数和去重后题数。
- 每组可复制、禁用、删除、重命名。
- 结构筛选、题号范围和最终候选题列表三层选择互补。
- 全卷题型配额必填；候选不足时显示请求数/可用数，由用户选择缩水生成或返回调整。
- 预览后逐题移除不自动补题。
- 权重提供“均衡复习、优先薄弱题、优先新题、完全随机”预设；高级相对级别可选，不暴露内部公式。
- 离开时可保存一个最近组卷草稿；草稿不保存随机结果，重开时重新计算并提示题库变化。

### 4.4 组卷性能

- 筛选计数和正式生成优先由 Rust/SQLite 完成。
- 前端使用分页/虚拟滚动元数据；题图按需加载。
- 请求带题库修订号，过期结果不得覆盖新筛选。
- 正式试卷固定保存题目 ID、顺序、随机种子、生成时间和范围摘要。
- 题目被回收时保留历史试卷占位，不静默换题。

## 5. 第三阶段：错题方案与连续复习

### 5.1 每日队列

- 每个启用方案每天最多一个不可变队列。
- 仅学习日生成；休息日不生成新题。
- 顺延题先入队、按原顺序排列并占用配额。
- 顺延题超过配额时只保留队首，其余继续等待。
- 剩余配额才抽正常到期候选；顺延题不受题型比例拆分。
- 同方案同日同题不得重复。
- 候选不足允许低于目标，但必须显示题型缺口和原因。
- 已有队列再次进入不重抽；新导入错题按每日配额逐步消化。

### 5.2 反馈与撤销

- 不会：下一个学习日到期，连续失败次数增加。
- 模糊：3 个学习日后到期，连续掌握次数清零。
- 掌握：按连续掌握次数进入 7、14、30、60 个学习日间隔。
- 间隔跳过休息日。
- 重看今天不会的题不产生新历史、不改间隔、不改错误次数。
- 撤销只恢复最近一次正式反馈、队列状态、连续次数和下次到期日；不重建队列。

### 5.3 方案变更与连续会话

- 已生成历史队列不受方案编辑、暂停、启用或配额修改影响。
- 修改只影响下一个尚未生成的学习日。
- 暂停方案允许完成已有队列；删除默认保留历史和未完成队列。
- 方案顺序稳定，方案内队列顺序固定；当前方案完成后自动进入下一方案。
- 切页、刷新、重启后定位第一道未完成题。
- 撤销可跨方案回滚最近反馈。

## 6. 第四阶段：周期计划与月历

### 6.1 预览与事实

- 新建/编辑先生成月历预览，确认后才写正式排程。
- 已确认事项日期和状态是历史事实；修改节奏、总量、截止日期或休息日必须重新预览。
- 已完成事项不可被重排覆盖；缩量若越过已完成序号必须拒绝。

### 6.2 状态、顺延和撤销

- `pending`：可完成、跳过、参与顺延。
- `completed`：完成，不参与顺延。
- `skipped`：跳过本次，不算完成、不参与顺延、不因刷新恢复 pending。
- 完成、跳过、恢复和顺延使用 CAS、服务端时间和五秒 latest-only 撤销。
- 顺延必须服务端预览 → 用户确认 → 原子写入；显示影响数量、旧/新预计日期、休息日和超期天数。

### 6.3 月历与进度

- 月历只显示周期计划事项，不显示错题或复习方案。
- 日期格最多直接显示 3 项，其余显示数量；点击日期显示完整清单。
- 窄窗口使用日期列表/详情布局，不强压七列网格。
- 完成数是唯一主进度；跳过数独立显示；完成百分比为完成数/当前总量。
- 跨多日事项整项完成后才增加完成数。
- 预计超期显式显示，不自动改计划。

## 7. 第五阶段：搜索、AI 与 Provider

### 7.1 AI 不可成为前提

- AI 必须主动触发；手动计划、题库、复习、周期计划和备份不依赖 AI。
- 调用前显示 Provider、主机、模型、完整外发范围、Token 估算、输出上限和预算影响。
- 取消预览不产生请求；失败不影响本地核心功能。
- API Key 只存 Windows 凭据管理器，不进入 SQLite、备份、日志、缓存或诊断。

### 7.2 资料上下文

- 可选资料后，搜索只来自已选资料；未选资料时允许全库关键词搜索。
- 资料取消后，相关结果和已选片段立即移除。
- 最多选择 6 个页片段；最终预览只显示明确选择的片段。
- 无片段时仍可用手动输入生成草稿，但必须提示未引用本地资料。

### 7.3 AI 规划

- AI 最多返回 1–5 张计划卡片。
- 卡片可逐张编辑、接受或放弃；接受后进入本地计划编辑器。
- 最终必须经过月历预览和用户确认才落库。
- AI 不直接写正式计划、不生成数百条日任务。

### 7.4 错题解析

- 只从题目区域图片生成外发预览，不发送整页或整本 PDF。
- 结果固定标注“AI 参考解析，不是标准答案”。
- 按题目区域指纹缓存；区域变化使旧缓存失效。
- 解析不改变作答状态、复习间隔、计划或统计。

### 7.5 Provider 设置

- 设置首页只显示当前 Provider、模型/目的地、密钥状态、Token 摘要和管理入口。
- 管理窗口提供 Provider、预算、连接测试、调用历史四种模式。
- 高级限制默认折叠；连接测试也先预览再确认。
- 默认离线测试 Provider；不做自动路由、故障转移、余额脚本或遥测。

## 8. 第六阶段：思维导图

- OPML 与 FreeMind `.mm` 先生成只读草案，确认后创建正式导图。
- XMind 只保留源文件并提示先导出 OPML。
- 原始文件不改，重新导入创建新副本。
- 支持基础节点编辑、移动、排序、展开/折叠和持久化撤销/重做。
- 支持资料/PDF 页码关联；页码越界阻止保存。
- 图片/PDF 只浏览缩放；不做识图、OCR、AI 节点建议。
- 单图上限 2,000 节点、导入文件 100 MiB、深度 32。

## 9. 第七阶段：设置、备份、迁移与错误

### 9.1 备份恢复

- 创建完整备份：SQLite 一致快照、正式 Blob、导图、非敏感 AI 配置/缓存。
- 排除 API Key、临时文件、日志、锁文件、未管理文件。
- 恢复前验证 manifest、schema、迁移历史、外键、quick_check、Blob SHA-256。
- 恢复只生成新位置的独立副本，绝不覆盖当前工作区。
- 失败保留原工作区和原备份，不做覆盖式修复。

### 9.2 迁移与卸载

- 所有 schema 只增量迁移，不删除历史数据。
- 升级后首次启动必须验证旧工作区、备份恢复和外键/完整性。
- 卸载默认保留用户数据，文档明确说明数据位置和删除方法。

### 9.3 错误与诊断

- 每个跨边界错误使用稳定错误码、人话说明和可执行建议。
- 不向 WebView 暴露 SQL、绝对路径、storage key、内部 JSON、堆栈、原始 Provider 响应或密钥。
- 设置 → 数据 → 运行诊断提供脱敏摘要；用户主动导出前显示内容预览。
- 诊断包不含学习资料、PDF、题图、API Key、路径、SQL、请求正文或 AI 响应。

## 10. 测试与验收要求

### 10.1 代码级测试

每个实现批次先执行：

```powershell
pnpm check:target -- <changed files>
```

Rust 模块按最窄范围执行 `cargo check`、目标模块测试和 Clippy。只有涉及迁移、事务、跨层 DTO、备份或 Tauri 命令时才扩大测试范围。

### 10.2 桌面验收证据

每条链路必须记录：版本/构建来源、样本或操作前提、步骤、预期、实际结果、失败截图或稳定错误码。历史验收文档不能直接替代当前版本证据。

必须覆盖：

- 全新 Windows 用户安装、首次启动和轻量引导；
- 文本/扫描/混合/多科目/损坏 PDF；
- 约 1000–1300 题真实资料的进度、取消、失败重试；
- 批量登记、缩水组卷、范围组、草稿恢复、重复题号；
- 多方案连续复习、顺延、反馈、撤销和重启恢复；
- 周期计划预览、完成/跳过/恢复、顺延预览、CAS 冲突和缩量保护；
- AI 外发预览、取消、缓存、断网和无 API Key 降级；
- 思维导图导入草案、基础编辑、撤销/重做和 PDF 关联；
- 完整备份、恢复独立副本、升级迁移和卸载保留数据。

## 11. 最终发布门槛

只有在当前批次准备交付时，按顺序各执行一次：

```powershell
pnpm check
cargo fmt --all --manifest-path src-tauri\Cargo.toml -- --check
cargo test --locked --manifest-path src-tauri\Cargo.toml
cargo clippy --locked --all-targets --manifest-path src-tauri\Cargo.toml -- -D warnings
pnpm tauri build --no-bundle
```

任一命令失败必须先修改原因，再重新进入受影响的门禁；不得只为获取更多日志而盲目重跑。

发布前硬性条件：

- 自动门禁全部通过；
- 当前版本所有首版范围行为均有桌面验收证据；
- P0/P1 缺陷为 0；
- P2 缺陷均有影响、复现条件、规避方法和后续计划；
- Windows 10/11 x64 的 NSIS 与 ZIP 产物可获得；
- GPL-3.0、隐私说明、安装/卸载、备份恢复、已知限制和反馈渠道齐全；
- Git 跟踪范围已审计，无 API Key、个人资料、绝对路径、临时目录或构建产物；
- 依赖许可证清单完成并可解释；
- 从干净提交创建 `v0.1.0` 标签，Release 只挂载该标签构建产物。

## 12. Agent 工作协议

每个新 agent 开始前必须：

1. 阅读本文件、`AGENTS.md`、最近实现文件、直接契约和对应测试；
2. 报告当前阶段、负责文件、已知缺口和不修改范围；
3. 只处理一个清晰链路，避免跨阶段混改；
4. 保留其他 agent 或用户的未提交修改，不执行破坏性 Git 操作；
5. 修改后先查看 diff/变更范围，再运行目标门禁；
6. 在交接报告中写明改动、验证命令/结果、未完成项、桌面验收步骤和风险。

交接报告模板：

```text
阶段：
负责范围/文件：
已完成行为：
未完成行为：
目标验证：
桌面验收步骤：
已知风险/P0-P2：
下一 agent 建议：
```

本文件只定义规划和执行边界，不宣称任何尚未执行的桌面验收或发布门禁已经通过。
