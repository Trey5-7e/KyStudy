## 实现范围

### 科目管理

- 创建名称最长 40 个字符的科目，并从固定颜色键中选择标记颜色；
- 同一工作区内的有效科目名称不区分大小写且不能重复；
- 科目列表同时返回有效科目和已归档科目，有效科目稳定排在前面；
- 归档是可确认的状态变更，不删除科目，也不删除或改写已经关联的任务；
- 已归档科目不会出现在快速新建任务的科目选项中；
- 已经关联归档科目的任务仍显示原科目名称，编辑其他字段时也可以继续保留该关联；
- 任务一旦改为未分类或其他有效科目，就不能重新分配到已归档科目。

M2-004 暂不提供恢复归档、科目改名和拖拽排序。这些操作需要先明确历史与冲突规则，不能用删除或直接覆盖代替。

### 任务详情

详情面板可以修改：

- 标题；
- 说明；
- 科目；
- 预计时长；
- 优先级。

计划日期在详情中只读，前端更新 DTO 也不包含 `plannedDate`。Rust Command 使用 `deny_unknown_fields`，即使绕过界面额外发送日期字段也会拒绝解析。日期调整必须进入 M2-005 的“延期”用例，以便记录原日期、新日期和原因。

详情面板还有以下保护：

- 没有实际修改时不能提交空编辑；
- 标题为空或预计时长超出 1～1,440 分钟时不能保存；
- 有未保存修改时关闭详情需要再次确认；
- 有未保存修改时不能直接执行状态操作，避免无提示丢失表单内容；
- 保存成功后由后端返回的正式任务替换前端状态，不在前端猜测持久化结果。

### 任务状态

M2-004 新增以下转换：

```text
todo --start--> in_progress
todo --complete--> done
in_progress --complete--> done
done --reopen--> todo
```

其他转换继续由领域层拒绝。开始、完成和重新打开都会在同一个 SQLite `IMMEDIATE` 事务中修改任务并追加不可变历史，分别写入 `started`、`completed` 和 `reopened`。

## 数据与事务边界

本工作项继续使用 schema v3，不新增迁移：

- `subject.archived_at` 保存归档时间；
- `task.subject_id` 保留对归档科目的外键；
- 任务详情更新与 `edited` 历史在同一个事务中提交；
- 新分配科目时，Repository 会检查该科目属于当前工作区且未归档；
- 如果任务原本已经关联该归档科目，且本次没有更换科目，则允许编辑其他详情；
- 保存详情不会修改计划日期、任务状态、完成时间、手动顺序或来源类型；
- 无实际字段变化时不更新时间，也不制造无意义的 `edited` 历史。

前端仍不能获得数据库路径、工作区 ID、SQL、`before_json`、`after_json` 或内部错误文本。
