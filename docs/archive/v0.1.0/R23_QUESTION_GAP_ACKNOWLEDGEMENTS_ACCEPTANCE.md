# R23 题目缺漏确认与稳定指纹验收

本轮在 R22 题目索引可靠性的基础上，为题号诊断增加可恢复的用户确认状态。确认只针对诊断指纹，不修改题目、PDF 或作答历史；本文件记录自动化证据和人工验收边界，不代表桌面人工验收已经执行。

## 1. 本批成果

1. schema v19 增加 `question_gap_acknowledgement`，按工作区保存用户确认过的异常指纹。
2. `duplicate`、`jump`、`non_numeric` 使用稳定内容指纹；同一异常可以确认、取消确认并在诊断窗口中恢复提示。
3. `missing` 仍然是补题建议，不允许确认“无需处理”，避免把尚未核对 PDF 的缺题永久隐藏。
4. 诊断默认只统计待处理异常；用户可以切换“显示已确认”，并对已确认的异常执行“恢复提示”。

## 2. 稳定指纹与确认边界

诊断 key 使用竖线分隔，具体内容如下：

- `duplicate|前题 ID|前题解析数字|当前题 ID|当前题解析数字`：同时包含重复相邻题号两侧的题目 ID 和数字题号。
- `jump|前题 ID|前题解析数字|当前题 ID|当前题解析数字`：同时包含异常跳号两侧的题目 ID 和数字题号。
- `non_numeric|题目 ID|题号.trim()`：保留非纯数字题号的原始 `trim()` 文本，不做语义改写。
- `missing|...`：只用于缺题建议和相对补题，不写入确认表，也不提供确认按钮。

因此，只有 `duplicate`、`jump` 和 `non_numeric` 可以执行“确认无需处理”或“恢复提示”。题号发生变化时，包含该题号的指纹随之变化，旧确认不会压制新的异常；确认状态也不会跨题目或跨题号复用。

## 3. Schema v19 数据边界

`question_gap_acknowledgement` 的正式字段和约束如下：

| 字段              | 约束                                      |
| ----------------- | ----------------------------------------- |
| `workspace_id`    | `TEXT NOT NULL`，外键引用 `workspace(id)` |
| `issue_key`       | `TEXT NOT NULL`，数据库长度检查为 1～500  |
| `acknowledged_at` | `INTEGER NOT NULL`，确认或更新时间        |

表声明为 SQLite `STRICT`，主键为复合键 `(workspace_id, issue_key)`。工作区删除时由 `ON DELETE CASCADE` 清理确认记录；题目、PDF 分段或 PDF 本体没有反向外键，不会因为对象删除而误删或改写指纹记录。应用层会 trim key 并只接受 `duplicate|`、`jump|`、`non_numeric|` 前缀；确认 `true` 使用工作区和 key 幂等 upsert，确认 `false` 删除该行并恢复诊断提示。

确认行属于正式用户确认内容，完整工作区备份必须包含数据库中的这些行，恢复后由 schema v19 继续提供。确认表不携带 PDF、Blob、OCR 文本或临时文件；可重建的全文索引和渲染缓存仍按通用备份边界处理，不能替代确认记录。

4. 修改同一题的题号（包括非数字题号的文字变化），重新运行诊断，确认新的 key 仍显示，旧确认不会遮蔽新的异常。
5. 在多个科目、练习册、章节或题型范围之间切换，确认诊断范围和确认状态不会串组；关闭窗口、返回题目列表和再次进入时筛选范围保持可理解。
6. 对包含确认记录的工作区执行完整备份和恢复，确认恢复后的确认列表一致；删除工作区后确认记录应随 `ON DELETE CASCADE` 清理。

## 6. 验收边界

- 确认只改变诊断提示的默认可见性，不自动创建、删除或修改题目。
- 稳定 key 不保存题目正文或 PDF 内容；若题目 ID、题号或异常两侧发生变化，应按新指纹重新人工判断。
- 后端错误通过既有题库错误映射返回稳定错误码和用户可读提示，不把 SQLite 路径、SQL 或内部栈信息暴露给 WebView。
