## 实现范围

### schema v3

- 新增 `subject`、`task` 和 `task_change`；
- M1 的 workspace、资料、Blob、后台任务和备份数据保持原样；
- 迁移只新增表和索引，不删除或改写用户数据；
- 科目名称、颜色键、任务日期、预计分钟、优先级和状态由领域与 SQLite 双重校验；
- 创建任务与 `created` 历史在同一个 `IMMEDIATE` 事务中完成；
- 完成或重新打开任务时，状态修改与历史追加在同一个事务中完成。

`study_session` 尚未创建，实际学习记录进入 M2-007 后再迁移，避免提前留下未使用空表。

### 受控 Command

新增的 Command 为：

- `list_subjects`；
- `create_subject`；
- `list_tasks_for_range`；
- `create_task`；
- `transition_task`。

任务 ID 由 Rust 生成。前端不能发送 SQL、数据库路径、任意查询、审计 JSON 或自定义状态；DTO 也不会返回这些内部信息。当前只接受 `complete` 和 `reopen` 两种状态转换。

### 今日任务界面

- 根据工作区 IANA 时区计算默认日期；
- 可以切换要查看的本地日历日期；
- 可以输入标题、可选预计分钟和高/普通/低优先级；
- 列表按状态、优先级、手动顺序、创建时间和 ID 稳定排序；
- 可以快速完成任务，再次点击可重新打开；
- 显示完成数量和计划分钟；
- 对加载、空列表、缺少工作区、非法输入和后端失败提供明确状态；
- 快速完成不强迫用户填写学习时长或复盘。

异步加载使用递增请求编号，只接受最后一次日期请求的结果，避免快速切换日期时旧响应覆盖新页面。任务更新使用函数式 React 状态更新，不依赖闭包中的旧列表。
