# M9：资料驱动的 AI 规划闭环实施计划

| 项目     | 内容                                                                 |
| -------- | -------------------------------------------------------------------- |
| 状态     | implemented                                                          |
| 前置条件 | M8.1 统一综合验收已通过                                              |
| Schema   | v12                                                                  |
| 目标     | 用用户明确选择的资料页完成可追溯规划对话，并人工复制为待确认计划草案 |

## 1. 本批次交付

1. 在“规划”页面增加独立的 AI 规划工作区，不改变既有手动计划编辑器；
2. 对话保存在本地，支持多段对话和最近消息恢复；
3. 复用 M7 本地全文搜索，只有正文页码结果可以被勾选为上下文；
4. 每轮最多选择 6 个 PDF 页码，后端按文档 ID、页码和搜索词重新解析真实索引片段；
5. 每个片段最多进入 1,200 个字符，历史最多使用最近 8 条消息和 6,000 个字符；
6. 规划回复输出上限最多 1,800 Token，确保回复仍适合作为可编辑计划概览；
7. 调用前显示目标 Provider、完整组合文本、引用标签和最坏 Token 值；
8. 问题、资料或历史变化后，旧预览失效；执行时后端再次组合并比对完整文本；
9. 调用完成后保存用户问题、助手回复、Token 调用和 PDF 页码引用；
10. 回复中的来源按钮可回到原 PDF 页，前端不接收片段哈希、调用 ID、路径或内部索引 ID；
11. 用户可以把最后一条完整助手回复复制为 `draft` 计划，并自动附加当轮资料页码；
12. 草案仍需人工编辑和“确认为当前计划”，不会自动创建阶段、任务或日程；
13. 对话、引用和草案进入完整本地备份，API Key 仍不进入备份。

## 2. Token 控制

M9 不自动读取整份 PDF，也不把全部历史反复发送。上下文来自用户当前明确选择的页码，后端只取一个相关索引片段；多轮对话只带最近 8 条消息并设置总字符上限。最终完整组合文本仍需用户逐字核对，工作区单次/每日/每月预算继续生效，相同请求继续复用 M8 缓存。

## 3. 数据与安全边界

- 浏览器只保存当前界面状态，不把对话、资料片段或密钥写入 `localStorage`；
- AI 输出不能直接成为活动计划，更不能直接修改日程；
- `ai_context_ref` 保存来源、哈希和 Token 估算，不复制完整 PDF 原文；
- Provider 原始错误、SQL、路径、请求指纹和系统密钥不跨越 Command 边界；
- 索引缺失、页码变化或预览内容变化时拒绝执行，并要求重新预览。

## 4. 后续扩展

后续根据实际使用反馈增加对话重命名/归档、长对话摘要、结构化阶段候选与逐项差异确认。OCR、图片上下文、题目分析、自动阶段生成和自动写入日程不属于本批次。
