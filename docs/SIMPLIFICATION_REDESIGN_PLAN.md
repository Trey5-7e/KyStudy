# KyStudy 产品简化整改实施方案

| 项目 | 内容 |
| --- | --- |
| 状态 | R1～R7 已全部通过人工验收；简化整改阶段完成 |
| 基线 | 当前 `main`、SQLite v16，R5 + R6 不新增迁移、不改写历史数据 |
| 原则 | 先隐藏、后替换、再清理；不以删除数据换取界面简化 |
| 更新时间 | 2026-07-29 |

## 1. 背景

M1～M13 建立了可靠的本地文件、SQLite、PDF、OCR、AI、计划、导图、题目、错题和备份基础，但产品逐渐围绕工程对象和完整任务管理能力组织。用户需要理解并维护任务、科目、阶段、计划版本、优先级、时长、分析、知识节点和多种状态，操作成本开始高于辅助价值。

整改目标不是推翻已有工程，而是重新确定默认用户路径：

```text
设置一次目标和范围
→ KyStudy 自动安排
→ 用户处理今天
→ 只给必要反馈
→ 系统更新下一次安排和进度
```

详细需求见 [PRD v0.2](PRD.md)，页面结构见 [信息架构 v0.2](INFORMATION_ARCHITECTURE.md)。

## 2. 已确认的不可回退决策

### 2.1 产品与导航

- KyStudy 是个人备考辅助工具，不是商业任务管理产品；
- 一级导航只有今日、计划、习题册、错题、资料；
- AI、分析、导图和数据管理不再作为一级入口；
- 学习分析只保留每份计划的完成数量、百分比和预计完成日期。

### 2.2 错题

- 题目拥有科目、习题册、题型和可选章节；
- 习题册提供默认科目，单题可覆盖；
- 题型自动识别并始终可手动修改；低置信度时必须手动选择；
- 支持多份按科目、书籍和题型数量配置的复习方案；
- 题型不足时用方案范围内其他到期题补足；
- 休息日不生成队列；
- 未完成题顺延到队首并占用次日配额；
- 当天“不会”不强制追加，完成后可选重看；
- 正式反馈只有不会、模糊、掌握；
- 题目以图片卡片和大图弹窗展示，不跳转完整 PDF；
- AI 解析主动触发、图片优先、本地缓存，不参与复习算法。

### 2.3 周期计划与月历

- 快速表单和 AI 整理并存；
- 默认采用节奏优先；
- 多学习日内容作为一个连续事项；
- 未完成可以一键顺延后续计划；
- 超过截止日期仍可保持原节奏，但必须警告并提供重新规划；
- 计划页默认使用按月展示的日历；
- 错题计划不进入月历；
- 用户自行选择哪些周期计划显示；
- 月历事项使用点击卡片操作，不支持拖拽。

### 2.4 思维导图

- 导图是可简单修订的阅读器，不是完整编辑器；
- 结构化文件导入后保留原文件并建立本地副本；
- 只提供基础浏览、搜索、折叠和节点增删改移动；
- 图片和 PDF 只浏览，不做 AI 节点转换；
- 优先验证成熟导图库，不继续扩展自研完整编辑器。

### 2.5 旧功能

- 第一阶段先隐藏，不删除数据库和历史数据；
- 新体验稳定并完成恢复测试后，才讨论永久清理；
- 现有 M13 计划进度能力优先复用。

## 3. 改造边界

### 3.1 必须保留

- SQLite 迁移历史和未知篡改拒绝机制；
- 本地 Blob 导入、去重、取消和恢复；
- PDF 受控读取与多区域坐标；
- 本地 OCR 和搜索基础；
- AI Provider、密钥安全存储、预算和外发预览；
- 备份、恢复和跨目录副本；
- 现有用户题目、错题、计划和学习记录；
- 自动测试、Clippy 和 Release 构建门槛。

### 3.2 本轮不做

- 删除旧表或压缩迁移历史；
- 云同步和账户；
- 发布、许可证和开源准备；
- 移动端；
- 完整 XMind 或日历编辑能力；
- 图片导图 AI 转换；
- 通用自由标签系统；
- 复杂记忆模型和预测分析。

## 4. 实施阶段

### R0：文档与范围冻结

目标：让 README、PRD、信息架构和实施计划使用同一套产品语言。

交付：

- README v0.2 产品定位；
- PRD v0.2；
- 信息架构 v0.2；
- 本实施方案；
- 旧 M1～M13 文档保留并标记为历史工程记录。

退出条件：用户确认文档准确，业务代码仍未改变。

### R1：应用壳与默认路径瘦身

状态：**accepted（2026-07-28）。** 详细结果见 [R1 验收清单](R1_SIMPLIFICATION_ACCEPTANCE.md)。

目标：先让产品结构变简单，不碰核心数据。

交付：

- 一级导航收缩为 5 项；
- 设置聚合 AI、数据和全局学习日；
- 今日页移除 Workspace 状态、时长和复杂统计；
- 旧页面从默认导航隐藏，但保留内部路由或适配入口；
- 建立新页面的懒加载与错误边界。

自动验证：

- 合法页面解析和页面记忆；
- 键盘焦点、按钮语义和窄窗口布局；
- 隐藏旧入口不影响相应 Command；
- 现有工作区继续打开。

人工验收：打开应用后 10 秒内找到今日计划、错题、月历和设置。

### R2：题目分类与复习方案

状态：**accepted（2026-07-29）。** 详细结果见 [R2 验收清单](R2_REVIEW_SCHEME_ACCEPTANCE.md)。

目标：完成“用户不用挑题”的每日错题闭环。

数据增量：

- 习题册默认科目；
- 题目科目覆盖和题型；
- 自动分类结果、置信度和人工覆盖来源；
- 复习方案；
- 方案习题册范围；
- 方案题型配额；
- 队列顺延顺序所需的稳定字段。

数据规则：

- 书籍继续由现有 `document_id` 表达，不新增重复书名事实；
- 现有 `chapter` 继续复用；
- 旧题目迁移后可以继承习题册默认科目；
- 无法推导的旧题型进入受控待分类状态，不伪造结果；
- 不删除现有人工优先级和知识关系字段，但新算法不依赖用户填写。

应用交付：

- 习题册一次设置默认科目；
- 框选后的自动分类和手动四按钮；
- 批量分类旧题目；
- 多份复习方案；
- 题型配额校验；
- 方案范围内补足；
- 多本书同紧急度分散；
- 顺延题占配额并固定队首；
- 全局休息日支持。

算法验证至少覆盖：

- 题型配额满足和不足；
- 禁止跨方案科目或书籍补题；
- 多日未完成顺序稳定；
- 顺延数量大于、等于和小于每日配额；
- 休息日跳过；
- 同一道题不跨方案重复出现；
- 不会、模糊、掌握的下一次间隔；
- 重看不会题不改变正式计数。

### R3：卡片式错题体验

状态：**accepted（2026-07-29）。** 详细结果见 [R3 + R4 合并验收](R3_R4_COMBINED_ACCEPTANCE.md)。

目标：用户不打开完整 PDF 即可完成一轮复习。

交付：

- 多区域题目卡片；
- 图片滚动、缩放和拖动；
- 轻量大图弹窗；
- 不会、模糊、掌握三个大按钮；
- `1 / 2 / 3` 快捷键；
- 自动进入下一题；
- 撤销上一次反馈；
- 完成页和可选重看；
- 移除默认耗时、答案笔记、下拉反馈和内部评分说明。

性能边界：题目图片按需加载，下一题可有限预取，不一次把整本 PDF 或全部队列渲染到内存。

### R4：周期计划规则与月历

状态：**accepted（2026-07-29）。** 详细结果见 [R3 + R4 合并验收](R3_R4_COMBINED_ACCEPTANCE.md)。

目标：让用户通过目标和节奏生成未来计划。

数据增量：

- 数量、单位、开始日、截止日；
- 每 N 个学习日完成 1 个单位；
- 多学习日事项进度；
- 计划级月历可见性；
- 顺延批次和原始计划日期；
- 预计超期状态。

需要评估现有 `plan`、`plan_stage`、`task` 和 `plan_stage_task` 是否能通过适配器承载新规则。优先复用现有任务和进度事实，不直接复制历史任务。

交付：

- 极简快速表单；
- 节奏优先排程；
- 均匀到截止日的可选模式；
- 休息日跳过；
- 多学习日事项；
- 精确月历预览；
- 按月日历、选中日期详情和计划筛选；
- 点击事项操作卡片；
- 整体顺延后续；
- 超期警告与加快频率、减少次数建议；
- M13 进度适配为数量与百分比。

日期算法验证至少覆盖：

- 月末、年末和闰年；
- 不同周起始日；
- 固定休息日；
- 多学习日跨休息日；
- 提前完成和超期；
- 顺延不改写已完成历史；
- 重新规划预览与确认幂等。

### R5：导图阅读器替换验证

状态：**accepted（2026-07-29）。** 详细结果见 [R5 + R6 合并验收](R5_R6_COMBINED_ACCEPTANCE.md)。

目标：验证成熟导图库能否替代自研复杂展示层。

先建立隔离技术验证，不直接替换正式页面：

- 固定版本安装到现有 pnpm 工作区；
- 禁止运行时 CDN；
- 验证 React 19、Tauri 和 CSP；
- 验证中文输入法、快捷键冲突和无障碍焦点；
- 验证 100、500、1000 节点性能；
- 建立 KyStudy 规范树与库数据之间的单向适配；
- 验证 `.xmind`、`.mm` 和 OPML 导入；
- 检查 MIT 许可证并更新依赖审计。

验证通过后交付：

- 资料页导图入口；
- 原文件与本地副本；
- 基础浏览、搜索和节点编辑；
- 持久化撤销与重做；
- 隐藏掌握度、重要度、笔记和复杂关系；
- 图片和 PDF 继续使用资料查看器。

验证失败时保留现有存储与解析层，选择 jsMind 或进一步缩减为只读树形浏览，不扩大自研编辑器范围。

### R6：情境化 AI

状态：**accepted（2026-07-29）。** 详细结果见 [R5 + R6 合并验收](R5_R6_COMBINED_ACCEPTANCE.md)。

目标：AI 只在能减少步骤的具体位置出现。

规划交付：

- 新建计划内选择资料和对话；
- 1～5 张结构化计划卡片；
- 单独修改、接受和拒绝；
- 本地月历预览与确认；
- 摘要、检索和请求缓存。

错题交付：

- 卡片内主动点击“AI 解析”；
- 题目区域图片优先；
- 多区域有序发送；
- 结果缓存和失效规则；
- 明确非标准答案提示；
- 不回写复习评分。

Token 验证至少覆盖：

- 未点击时零远程请求；
- 缓存命中不重复请求；
- 修改题目图片后缓存失效；
- 预算阻止和错误提示；
- 外发预览不包含整本 PDF、路径或密钥。

## 5. 依赖与技术策略

### 5.1 依赖原则

- 只为明显减少自研复杂度的成熟能力新增依赖；
- 固定精确版本并提交锁文件；
- 下载和缓存优先使用 F 盘既有开发环境；
- 新依赖必须检查许可证、包体积、离线能力和维护状态；
- 不引入运行时 CDN、账户或云服务作为基础功能前提。

### 5.2 数据迁移原则

- 当前 v16 为运行基线，v14、v15 继续作为受测试的历史升级基线；
- 新迁移只追加，不修改既有迁移内容；
- 迁移必须在事务中执行；
- 新字段需要为旧数据提供安全默认或显式待分类状态；
- 完整备份恢复覆盖新表和新关系；
- 未知迁移名称、版本或校验和继续拒绝打开。

### 5.3 适配器优先

优先通过受限 DTO 和适配器把旧数据映射到新界面，不让 WebView 直接处理旧内部表结构。新界面不得通过接收完整任务、题目或数据库快照在前端自行计算关键业务规则。

## 6. 质量门槛

每个整改阶段至少执行：

```powershell
pnpm check
cargo fmt --check --manifest-path src-tauri\Cargo.toml
cargo test --locked --manifest-path src-tauri\Cargo.toml
cargo clippy --all-targets --all-features --locked --manifest-path src-tauri\Cargo.toml -- -D warnings
pnpm tauri build --no-bundle
```

需要 Release 人工测试时，只提供详细步骤，由用户自行操作；除非用户明确要求，不进行桌面自动交互。

## 7. 整体人工验收主线

1. 打开旧 v14 工作区，确认数据与主页面正常；
2. 创建全局休息日和考试日期；
3. 30 秒内创建“20 套、每套 2 个学习日”的计划；
4. 在月历查看多日事项并切换月份；
5. 顺延后续计划并验证超期提示；
6. 导入一本习题册并设置一次默认科目；
7. 框选选择题，自动分类正确时一次保存；
8. 框选低置信度题目，手动选择题型后保存；
9. 创建高数 5 道和线代 5 道复习方案；
10. 验证题型不足时同范围补足；
11. 验证昨日 3 道未完成后今日仍为 5 道且顺延题在前；
12. 只使用三个反馈按钮完成卡片复习；
13. 主动调用一次图片 AI 解析，再次打开命中缓存；
14. 导入结构化导图并修改本地副本，确认原文件不变；
15. 完整备份并恢复到新目录；
16. 断网启动并完成计划、习题册、错题和导图基础流程。

## 8. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 一次重构过多导致回归 | 按 R1～R7 分阶段，每阶段独立验收 |
| 隐藏旧页面后仍有隐式依赖 | 保留路由适配与自动测试，先不删除 Command |
| 旧题目没有科目或题型 | 习题册默认继承、待分类状态和批量修正 |
| 题型配额造成队列饥饿 | 同范围其他到期题补足，不跨范围、不提前抽取 |
| 顺延导致截止冲突 | 允许保持节奏，明确警告并提供可选重新规划 |
| 导图库不兼容 Tauri | 隔离验证后再正式接入，准备 jsMind/只读降级 |
| 图片 AI 解析消耗较高 | 只发送裁剪区域、主动触发、哈希缓存和预算阻止 |
| AI 解题结果错误 | 明确风险标记，不参与复习算法，不冒充标准答案 |
| 数据模型继续膨胀 | 固定结构化维度，不先建设自由标签和通用规则引擎 |

## 9. 开始实施前的最后条件

在修改业务代码前必须完成：

- 用户确认 README、PRD、信息架构和本方案；
- 确认 R1 为首个实施阶段；
- 检查并保留当前工作区与备份兼容基线；
- 不把尚未确认的细节扩展为新功能；
- 新阶段需要人工验收时，先提供清晰步骤，不主动操作桌面。
