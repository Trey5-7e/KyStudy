# R26 1000 题导入、可见性与缺漏诊断验收

本轮针对现场出现的“高数 1000 题分段存在但为 0 题、筛选下拉只有 880”进行只读审计，
并收束稀疏文字层、OCR 合并、批内索引键、分段导入和缺漏诊断的边界。本文记录可重复的
证据、代码级验收计划和真实 PDF 预期基线；不代表本轮已经完成桌面人工验收。

## 1. 现场数据库只读证据

### 1.1 数据库定位与安全边界

Tauri `identifier` 为 `io.github.kystudy.desktop`，应用数据目录由
`app.path().app_data_dir()` 提供。当前默认工作区数据库为：

```text
<LOCAL_APP_DATA>\io.github.kystudy.desktop\workspaces\default\kystudy.sqlite3
```

本轮使用 Python `sqlite3` 的 `file:...?...mode=ro` URI 打开，仅执行 `SELECT` 和只读
元数据查询；没有执行 `INSERT`、`UPDATE`、`DELETE`、迁移、备份恢复或任何桌面操作。
现场读数为 SQLite `user_version = 19`，日志模式为 WAL。

### 1.2 分段与题目计数

以下为同一工作区的只读聚合；`题目行`只统计 `question.deleted_at IS NULL` 且存在
`question_index_metadata` 的正式题目。

| 科目 / 练习册      | PDF 分段      | `index_state` | 分段 `question_count` | 题目行 | 结论                   |
| ------------------ | ------------- | ------------- | --------------------: | -----: | ---------------------- |
| 高数 / 1000 题     | 第 3～296 页  | `pending`     |                     0 |      0 | 分段已保存，索引未完成 |
| 线性代数 / 1000 题 | 第 3～91 页   | `ready`       |                   224 |    224 | 现场成功结果           |
| 概率论 / 1000 题   | 第 92～214 页 | `pending`     |                     0 |      0 | 分段已保存，索引未完成 |
| 高数 / 880         | 第 3～98 页   | `ready`       |                   655 |    655 | 既有可浏览题目         |
| 线性代数 / 880     | 第 3～46 页   | `ready`       |                   259 |    259 | 既有可浏览题目         |
| 概率论 / 880       | 第 47～82 页  | `ready`       |                   202 |    202 | 既有可浏览题目         |

线性代数 / 1000 题的 `question_index_metadata` 有 225 行，其中 1 行对应已删除题目，
因此分段计数和当前可浏览题目均为 224；这是回收站语义，不是重复显示。

结论是两部分同时成立：

1. 高数 / 1000 题分段的 0 题不是前端筛选造成的，数据库中确实没有可浏览题目行；
2. 筛选下拉只有 880 另有前端可见性原因：练习册选项从当前 `snapshot.questions`
   推导，零题分段不会产生 1000 选项。分段树仍从 `snapshot.segments` 构建，所以能看见
   1000 题分段及其 `pending / 0` 状态。

## 2. 根因与本轮修复边界

### 2.1 稀疏文字页不应误触 OCR

旧路径只按正文文字项数量和字符数判断稀疏页。某些页面虽然文字层稀疏，但已经有可靠的
顶层题号及题干；可选 OCR 仍会补入同一题号的 OCR 文字，造成文字层/OCR 题号候选重复。
本轮边界为：

- `pageNeedsOcr` 先检查题号标记是否已经有可靠题干；有可靠题号和正文时走文字层，不因
  页面总字符数较少而启动 OCR；
- 仍然没有可靠题号或正文不足的页面才允许逐页 OCR；OCR 结果始终是低置信度候选；
- OCR 与文字层合并时按归一化文本和坐标去重，跨来源的同一题号只保留一个标记；同一
  来源的两个真实题号不因位置相近而静默合并。

### 2.2 批内 source key 与旧键幂等

索引器的基础键包含章节、篇章、题型、原题号和 PDF 页码。OCR/文字合并或同页重复锚点
可能产生相同基础键；后端导入会拒绝同一批次中的重复 `source_key`。本轮要求：

- 同一批次内基础键重复时增加稳定的出现序号，保证批内唯一，不依赖随机 UUID；
- 仍完全相同的旧 `source_key` 重跑必须命中既有 `(segment_id, source_key)`，复用原题 ID，
  不新增题目、不清空作答历史；
- 自动重导不能覆盖已经人工校正的区域或手动分类；新键只代表新的索引候选，需按正常
  人工校对边界处理。

### 2.3 分段先存造成“分段有、题目为 0”的表象

前端先调用 `save_workbook_segments` 建立 `pending / question_count = 0` 的分段，再按科目
逐段调用 `import_question_index`。若后续批次因重复键、区域越界、取消或其他输入错误失败，
已保存的分段会保留，而题目事务不会提交，因此出现现场的 `pending / 0`。这不是伪造题目，
但必须让用户看到可解释的中间状态。

本轮要求：

- 每一段导入成功后立即通过 `onImported` 发布最新快照，前面已完成的科目不再表现为整体
  失败；
- 后续失败提示固定包含“已完成 n/m，失败科目可重试”，并保留已完成快照；
- 重试继续使用现有分段唯一键，复用原 `pending` 分段，不重复建立分段或题目；同一次
  导入会跳过已成功科目，优先重试失败科目；
- `pending / 0` 只能显示为待建立/待重试，不得被当作可浏览题目或参与拼卷。

### 2.4 缺漏诊断不能被题型筛选截断

题型可能在同一章节/篇章内重新从 1 编号。只对当前题型数组诊断，会把另一个题型的合法
题号误报为缺题；只把所有题型混在一条链，又会把独立编号误合并。本轮诊断边界为：

- 分组至少包含 PDF 分段、章节和篇章，不跨分段或章节推断连续性；
- 诊断接收当前可见题目和同一工作区的未筛选上下文；题型筛选只控制显示，不丢失上下文；
- 只有全局单调或每题型单调证据充分时才推断缺题；不确定的题型切换只给重复/跳号检查；
- 缺题建议、重复题号、异常跳号和非数字题号保持既有 R21～R23 的确认边界，页面空白
  本身不自动创建题目。

## 3. 数据与输入约束

- 每道题至少有一个区域，最多 **12 个 regions**；导入、区域替换和相对补题使用同一上限。
- 章节、题目标题和题号在进入 Rust 前按 UTF-8 字节预算裁剪；章节预算为 **120 字节**，
  裁剪不能截断多字节字符，并在需要时保留省略号。Rust `required_text` 继续执行 trim、
  非空和字节长度校验。
- OCR 页面候选不写入 `resource_page_text`、`question_region_ocr` 或正式作答历史；只有
  用户确认后的索引题目才进入既有导入事务。
- 旧数据库、旧 source key 和旧题目区域必须可重开；任何导入失败都不能留下半条题目、
  错误顺序或作答历史丢失。

## 7. 安全边界与结论

- 本轮数据库查询只读，不修改用户 SQLite、Blob、PDF、OCR 组件或作答历史。
- OCR 仍是低置信度候选通道，不是自动建题、公式识别或答案判定通道；缺组件、取消和
  识别失败必须回到文字层/手动框选，不静默补题。
- 代码级门禁和真实 PDF 回归已达到本节记录的结果，但尚未进行桌面窗口、Release WebView、
  OCR 组件交互或视觉区域人工验收；这些步骤不能由代码级测试替代。
- 本轮及本次结果记录均未写入用户数据库；现场数据库证据仍来自只读连接。
