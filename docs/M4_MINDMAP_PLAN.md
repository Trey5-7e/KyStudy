# M4：可编辑思维导图与结构化导入

| 项目     | 内容                                                       |
| -------- | ---------------------------------------------------------- |
| 状态     | ready-for-acceptance                                       |
| 目标     | 把备考知识结构变成可手动维护、可导入、可追溯的本地思维导图 |
| 验收方式 | 自动门槛完成后，一次性执行 Release 综合验收                |

## 1. 本批次交付

1. 创建、重命名、复制和删除思维导图；
2. 节点新增、编辑、删除子树、拖动换父级、同级上移/下移、展开/折叠；
3. 节点详情保存 Markdown 笔记、掌握状态和 1-5 重要度；
4. 节点可关联整份资料或 PDF 页码范围，并能回到原 PDF 页；
5. 每次正式修改形成独立 Revision，支持持久化撤销和重做；
6. 从已上传的 OPML 或 FreeMind `.mm` 生成独立导入草案；
7. 草案显示节点数、层级预览和格式警告，用户确认后才创建正式导图；
8. 全部功能离线运行，并进入既有完整备份与恢复边界。

## 2. 格式边界

首批正式结构化导入格式为：

- OPML 2.0/1.x：读取 `<outline text="...">` 或 `title` 的树结构；
- FreeMind `.mm`：读取嵌套 `<node TEXT="...">`；
- KyStudy 手动导图：使用内部节点模型，不保存任何前端组件私有结构。

XMind `.xmind` 仍可作为 `mindmap_source` 上传，但本批次不直接解压。XMind 新旧版本分别使用 JSON/XML ZIP 容器，若在未完成格式样本验证前直接支持，容易静默丢失多画布、关系、备注和附件。界面会明确提示先从 XMind 导出为 OPML 后再导入。

图片/PDF 识图依赖 OCR/视觉模型，留到 AI 与 OCR 边界具备 Token 预算和草案差异能力后实现。

## 3. Schema v6

- `knowledge_map`：导图标题、可选科目、根节点、当前 Revision 和软删除状态；
- `knowledge_node`：父子关系、标题、笔记、掌握状态、重要度、排序和折叠状态；
- `knowledge_node_resource`：节点到资料或 PDF 页码范围的正式关联；
- `knowledge_map_revision`：完整的内部业务快照，用于持久化撤销/重做；
- `map_import_draft`：来源资料、格式、独立草案树、警告、状态和确认结果。

Revision JSON 和导入草案 JSON 只在 Rust/SQLite 内部使用；Command DTO 返回类型化节点与警告，不向 WebView 暴露原始 JSON、SQL 或内部存储字段。

## 4. 数据与安全约束

- 每张导图恰好一个根节点；根节点不能移动或删除；
- 节点不能移动到自己或自己的后代下面；
- 同级 `sort_order` 由 Repository 在事务中归一化；
- 单张导图首版最多 2,000 个节点，单次导入最大 4 MiB、最大深度 32；
- XML 采用有界流式解析，拒绝 DTD，不执行外部实体或网络请求；
- 导入失败、拒绝草案或格式不支持都不能修改正式导图；
- 已知 PDF 页数时，节点资料关联不能越界；
- 删除导图使用软删除，节点删除需要明确确认整个子树。

## 5. 本批次不实现

- 自由曲线、跨树关系线、多人协作或通用知识图谱推理；
- XMind ZIP、Markdown 大纲或 KyStudy 专用导出文件；
- 图片/PDF 识图、OCR、AI 节点建议和逐项 AI 差异；
- 题目、错题、正确率或薄弱度自动回写。
