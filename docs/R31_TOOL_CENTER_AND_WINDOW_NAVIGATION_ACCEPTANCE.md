# R31 工具中心与工具窗口导航验收

R31 收敛题库工具入口，并把工具选择、工具执行和返回路径放进同一套窗口状态模型。本文件记录当前实现的交互边界、借鉴来源、导航契约和验收基线；不扩展题库数据模型，不改变 R30 的 active-only 重新归类语义。

本文整理时没有重新执行测试、完整静态门禁、Tauri 构建或桌面操作。用户已明确确认 R31 的 Release WebView 桌面人工验收通过；第 6 节沿用已有 R31 定向验证证据，第 7 节保留原自动门禁记录，不把本次文档整理当作新的执行结果。

## 2. 入口收敛与工具中心

### 2.1 题库主页入口

题库主页只保留三个固定入口，导入是唯一的主行动：

| 入口 | 层级 | 规则 |
| --- | --- | --- |
| `导入 PDF` | 唯一主 CTA | 从题库主页直接打开导入流程；不在工具中心重复提供导入卡片 |
| `题库工具` | 次级入口 | 打开 R31 两栏工具中心，按分组选择后续工具 |
| `分段回收站` | 次级入口 | 独立打开回收站流程，不混入工具卡片 |

工具中心侧栏明确提示：需要导入 PDF 时关闭工具窗口，回到题库主页使用唯一主 CTA。这样导入不会被埋进“分类”或“索引”分组，也不会在多个窗口重复出现。

### 2.2 两栏布局

工具中心是一个 `EditorDialog` shell 内的两栏布局：

```text
题库 / 工具
┌──────────────────────┬──────────────────────────────────────┐
│ 工具分组              │ 当前分组说明                          │
│ 分类                  │                                      │
│ 索引                  │  两列工具卡片                         │
│ 做题                  │  （标题 / 说明 / 状态 / 动作）        │
│ 维护                  │                                      │
└──────────────────────┴──────────────────────────────────────┘
```

左栏只切换分组，右栏只呈现当前分组的工具。当前实现的四个固定分组及工具如下：

| 分组 | 目的 | 工具卡片 |
| --- | --- | --- |
| `分类` | 建立题库层级 | `新建科目`、`新建练习册` |
| `索引` | 补题、校对和浏览 | `手动补题与校对`、`浏览题目索引` |
| `做题` | 登记结果和生成练习卷 | `快速登记做题`、`智能拼卷` |
| `维护` | 读取最新题库状态 | `刷新题库` |

工具中心不是第二个题库主页。它不显示重复的导入入口，也不在卡片上直接承载分段管理、回收站或后端事务。

### 2.3 卡片状态与禁用原因

卡片必须同时说明“当前可做什么”和“为什么暂时不能做什么”。禁用不使用只有颜色或半透明度的隐含提示，而通过可读文本和 `aria-describedby` 暴露原因：

| 条件 | 影响的卡片 | 用户可见状态或原因 |
| --- | --- | --- |
| 题库快照仍在加载 | 全部工具 | `正在读取题库状态，请稍候。`；卡片不可点击 |
| 没有活动 PDF 分段 | `手动补题与校对` | `请先导入并确认至少 1 个 PDF 分段。` |
| 没有已索引题目 | `浏览题目索引`、`快速登记做题`、`智能拼卷` | `请先建立题目索引。` |
| 正在刷新快照 | `刷新题库` | 卡片显示 `刷新中` / `正在刷新…`，关闭和重复提交均禁用 |
| 已具备前置数据 | 对应卡片 | 显示分段数、题目数、科目数或练习册数等状态 chip |

禁用原因是操作契约的一部分：它解释下一步动作，不泄漏 SQL、路径或内部错误。后端仍是数据和并发状态的最终权威。

## 3. 单一 activeWindow 与返回契约

### 3.1 一个活动窗口

题库窗口由一个 `activeWindow` 状态表示，同一时刻只存在一个活动变体，不通过多个 modal 堆叠表达历史路径。当前模型包含：

```text
undefined                         题库主页
{ kind: "tools", ... }            工具中心
{ kind: "segment-manager", ... }  分段管理
{ kind: "segment-trash" }         分段回收站
{ kind: "dialog", dialog, origin }
{ kind: "paper", questions, origin }
```

`dialog` 和 `paper` 都携带 `origin`。origin 只描述返回上下文，不改变题库数据；关闭窗口则统一回到题库主页。

### 3.2 origin 类型

| origin | 记录内容 | 适用子流 |
| --- | --- | --- |
| `root` | 题库主页 | 从主页直接导入、分类或做题 |
| `tools` | 工具分组和可选的 `focusTool` | 从工具中心打开科目、练习册、索引、登记或拼卷 |
| `segment-manager` | 活动分段 ID | 从分段管理进入浏览或继续索引 |

### 3.3 Back 与 Close

Back 和 Close 是不同意图，不能都简单映射为“关闭当前弹窗”：

| 当前子流 | Back 行为 | Close 行为 |
| --- | --- | --- |
| Tools child | 返回工具中心原来的分组，并恢复原卡片焦点 | 回到题库主页 |
| Manager child | 返回同一 `segmentId` 的分段管理窗口 | 回到题库主页 |
| Tools/manager 产生的 paper | 沿保存的 origin 返回来源窗口 | 回到题库主页 |
| origin 指向已不存在的分段 | 安全降级到题库主页 | 回到题库主页 |
| root child | 没有上一级 Back；使用关闭 | 回到题库主页 |

`questionBankBackTarget` 只计算返回目标，`questionBankCloseTarget` 始终清空活动窗口。分段在子流期间消失时，不返回失效管理器；工具窗口不会因为子流打开而保留第二个可见 modal。

### 3.4 Tools child 返回原 section

从工具中心选择任意非刷新卡片时，工具中心先退出当前可见窗口，再以 child dialog 打开目标工具，并记录：

```json
{
  "kind": "tools",
  "section": "index",
  "focusTool": "browse"
}
```

子窗口的 Back 会回到 `索引` 分组，并把焦点恢复到“浏览题目索引”卡片；不会回到默认的“分类”分组，也不会重新推断上一次入口。

### 3.5 Manager child 返回同一 segment

分段管理窗口的“浏览题目”和“继续索引”属于 manager child。它们使用：

```json
{
  "kind": "segment-manager",
  "segmentId": "<active-segment-id>"
}
```

因此 child Back 始终回到同一活动分段的管理概览。若该分段已被移除或不再出现在活动快照中，则返回题库主页并由上层清理失效窗口。

### 3.6 内部 browser 与 paper 子流

- `浏览题目索引` 在自身窗口内切换筛选、当前题、编辑、相对补题和缺漏诊断；这些内部子流提供“返回题目浏览”，不另建一条全局窗口栈。
- `智能拼卷` 先打开拼卷设置；生成题卷后转换为 `paper` window，同时保留原 origin。练习卷中的题目编辑、区域校正和作答保存仍在该子流完成。
- 从工具中心进入 paper 时，Back 返回“做题”分组并恢复“智能拼卷”卡片；从分段管理进入索引再产生 paper 时，Back 返回同一分段管理窗口。

## 4. dirty、busy 与焦点

### 4.1 dirty

所有编辑窗口通过统一 `EditorDialog` 处理未保存状态：

- 题目编辑、区域校正、分段重新归类等 dirty 状态在关闭或 Back 前显示放弃确认；
- 确认层提供“放弃修改”和“继续编辑”，不会静默丢弃输入；
- 清洁窗口可直接 Back 或 Close；
- dirty 判断属于当前窗口，不把未保存内容写入 origin 或浏览器历史。

### 4.2 busy

保存、刷新、删除、恢复和异步索引期间，窗口进入 busy 状态：

- 禁用重复提交、关闭、Back、遮罩关闭和会产生竞态的切换；
- 按钮显示下一步动作，例如 `正在保存…`、`正在刷新…`；
- 完成后使用后端完整快照更新题库，而不是拼接局部窗口状态；
- stale 或错误状态提供刷新、重试或关闭动作，不吞掉错误原因。

### 4.3 焦点和可访问语义

当前实现的验收重点包括：

- 工具分组使用 `role="tablist"`、`role="tab"` 和 `role="tabpanel"`，切换后恢复活动分组焦点；
- 工具卡片、关闭、Back 和危险操作都有可访问名称；禁用卡片的原因通过描述文本关联；
- 打开窗口后焦点进入标题、分组或指定卡片；关闭后恢复原触发按钮，触发器失效时使用页面备用焦点；
- 异步状态使用 `role="status"` / `role="alert"` 和礼貌播报，不依赖颜色传递结果；
- `Escape`、关闭按钮和遮罩关闭遵循 dirty/busy 规则；窗口打开期间锁定背景滚动；
- 所有核心操作可通过键盘完成，焦点状态可见，不依赖鼠标悬停。

## 5. 响应式边界

R31 保留两栏工具中心的桌面优先结构，同时为窄窗口提供明确降级：

| 视口条件 | 行为 |
| --- | --- |
| 大于约 900px | 左侧分组栏 + 右侧工具面板；工具卡片默认两列 |
| 不超过约 900px | 布局改为上下结构，分组栏变成可横向滚动的分组条 |
| 不超过约 640px | 工具卡片改为单列；面板标题和状态 chip 纵向排列；底部动作保持可见 |
| 不超过约 980px 的题目浏览 | 题目列表与当前题卡片上下排列，列表保持独立滚动区 |
| 不超过约 640px 的分段管理 | 元数据改为单列，动作按钮可换行，底部操作保持 sticky 可见 |

窄窗口验收不只看是否“能缩小”：标题、说明、卡片禁用原因和按钮必须换行而不重叠；独立列表滚动不能拖动背景页面；核心动作不能被折叠到悬停状态。

## 8. 桌面人工验收步骤（已通过）

应在隔离工作区或可恢复备份上执行，不直接试写唯一生产数据库。以下步骤构成已由用户确认通过的 R31 验收基线；本次只保留步骤和结论，不重新启动桌面应用：

1. 打开题库主页，确认 `导入 PDF` 是唯一主 CTA；`题库工具` 和 `分段回收站` 为次级入口，工具中心没有重复导入卡片。
2. 打开 `题库工具`，确认桌面宽度显示两栏，左栏四个分组，右栏只显示当前分组卡片。
3. 在有/无分段、有/无题目、加载中和刷新中分别检查卡片禁用状态、状态 chip 和可读原因。
4. 从每个可用工具卡片进入 child，确认工具窗口先退出、不会出现叠加 modal，并确认 child 标题、动作和 Back 文案正确。
5. 从 Tools child 点击 Back，确认回到原分组并聚焦原卡片；点击 Close，确认回到题库主页。
6. 从分段管理进入浏览或继续索引，确认 child Back 返回同一分段管理；分段失效时确认安全回到题库主页。
7. 进入题目浏览的编辑/缺漏诊断/相对补题子流，确认内部 Back 返回题目浏览；从拼卷设置生成 paper 后确认 paper 保留 origin 并按来源返回。
8. 在 dirty 窗口点击 Back、Close、Escape 和遮罩，确认出现放弃确认；在 busy 状态重复点击、关闭或切换，确认均被锁定。
9. 检查打开后的初始焦点、关闭后的触发器焦点、失效触发器的备用焦点、键盘顺序、可见焦点和 `role/status/alert` 播报。
10. 将窗口缩至约 900px、640px，并在题目浏览约 980px 以下检查单列/横向分组、独立滚动、按钮换行和底部动作可见性。

## 9. 集成边界与后续更新

- R31 只收敛题库工具入口和窗口导航，不改变 schema、题目 ID、PDF 区域、作答历史、复习状态或 R30 的 reassign 事务。
