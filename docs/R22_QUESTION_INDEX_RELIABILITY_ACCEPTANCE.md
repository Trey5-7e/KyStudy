# R22 题目索引可靠性验收

本轮在 R21 题目缺漏诊断的基础上，收束题目索引的异常提示、相对插入持久化和题库浏览器拆分。代码级回归用于确认规则与数据边界；桌面窗口、PDF 定位和视觉交互仍需按本文步骤人工验收，本文件不代表桌面验收已经执行。

## 1. 本批成果与自动化回归证据

1. 非纯数字题号会列入“需要检查”，并作为连续性运行的边界，不跨越它推断缺失题号。
2. 相邻纯数字题号仍按原规则诊断：小范围缺号可提示补题，相邻重复题号只提示定位检查，过大的相邻跳号提示异常跳号。
3. 相对补题的前后插入顺序在关闭并重新打开索引后保持稳定；失败事务回滚后不留下半条题目或错误顺序；手动调整过的题目区域不会被自动重新导入覆盖。
4. `QuestionBankPanel` 已将索引相关对话框拆分到 `QuestionIndexDialogs`，浏览、诊断、定位、补题、编辑和区域校正的对外行为保持不变。

代码级回归应覆盖题号诊断单测、题库模型与相对插入顺序、事务失败回滚、自动重导保留人工区域，以及 `QuestionBankPanel` / `QuestionIndexDialogs` 的类型与行为连接。上述证据不替代真实 PDF 和桌面交互检查。

## 2. 人工桌面验收步骤

1. 打开“习题册 → 浏览题目索引”，在同一 PDF 分段、章节、篇章和题型中准备连续纯数字题号，并插入一个如“例题 A”的非纯数字题号。运行“诊断缺漏”，确认该项计入“需要检查”，且非纯数字项前后的数字不会被错误判定为缺号。
2. 分别准备 `3 → 5`、相邻重复题号和明显大跨度题号，确认缺号、重复题号、异常跳号文案和“定位检查”操作仍正常；题号连续时确认窗口显示未发现明显缺漏。
3. 在题目前、题目后各执行一次相对补题，保存后关闭并重新打开索引，确认新题位置和后续题目顺序稳定。触发一次保存失败或取消操作后，确认索引没有残留半条题目或顺序移动。
4. 手动调整已有题目区域后重新执行 PDF 自动索引，确认人工区域仍保留；随后从题目列表进入诊断、定位、补题、编辑和区域校正，确认组件拆分后入口、筛选范围、关闭返回和当前题选择均与原流程一致。

## 3. 验收边界

- 自动化验证负责纯函数规则、排序与上限、模型顺序、事务原子性、区域保护和组件连接等可重复断言。
- 仍需人工确认 PDF 页面的实际题号、定位页是否正确、区域覆盖是否贴合内容，以及桌面窗口在真实数据下的筛选和返回体验。
- 页面空白、非纯数字题号和 OCR/目录异常只产生检查提示，不自动创建题目；最终是否补题仍由用户查看 PDF 后确认。
