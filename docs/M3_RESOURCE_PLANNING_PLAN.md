# M3：规划资料阅读与个人计划草案

| 项目     | 内容                                                 |
| -------- | ---------------------------------------------------- |
| 状态     | completed                                            |
| 目标     | 把已导入资料变成可阅读、可定位、可引用的个人计划依据 |
| 验收方式 | 自动质量门槛完成后，一次性执行 Release 综合验收      |

## 1. 本批次交付

M3 不接入 AI，也不以文字提取、OCR 或检索为前置条件。本批次先完成一个完全离线的人工闭环：

1. 用户从资料库打开已登记的 PDF 或图片；
2. PDF 支持上一页、下一页、页码跳转、缩放和旋转；
3. 应用保存 PDF 总页数、最后阅读页和最后打开时间；
4. 用户建立、编辑和确认个人计划，按阶段记录时间范围与重点；
5. 用户把资料的单页或连续页码范围引用到计划，并补充用途说明；
6. 引用可直接回到对应 PDF 页码，形成“资料 -> 计划 -> 原页复核”的闭环。

图片在本批次支持受控打开和缩放查看；图片区域标注、OCR 和跨图片引用留到后续迭代。

## 2. 安全与性能边界

- React 只获得不透明 `document_id`、显示元数据和业务页码；
- 不向 WebView 返回绝对路径、storage key、SQL、内部错误或整本 Base64；
- PDF.js 6.1.200 与 Worker 本地打包，并在用户打开 PDF 时动态加载；
- PDF 继续使用 `kystudy-pdf` 自定义协议，严格要求单 Range，单次响应不超过 1 MiB；
- 协议只能打开数据库中登记且完整性状态为 `ok` 的对应 Blob；
- 新页面渲染开始前取消旧 RenderTask，关闭阅读器时销毁 LoadingTask；
- 图片使用独立只读协议按 document ID 加载，不授予通用文件系统能力；
- 阅读进度按 document ID 保存，不把缩放和旋转当作资料内容的一部分。

## 3. Schema v5

### 3.1 资料阅读

- `resource_document.role`：`planning`、`reference`、`workbook` 或 `other`；
- `resource_document.page_count`：PDF.js 成功打开后回填，可空；
- `resource_reading_state`：最后阅读页、最后打开时间和更新时间。

### 3.2 个人计划

- `study_plan`：计划标题、目标考试、考试日期、总体说明、状态和修订号；
- `plan_stage`：阶段标题、起止日期、阶段重点和排序；
- `plan_reference`：计划、资料、起止页码和引用说明。

`draft -> active` 必须由用户显式确认。确认不自动创建日程任务；计划到日程的映射将在后续迭代单独设计，避免当前阶段发生隐式写入。

## 4. 错误与降级

- 未登记、非 PDF、损坏或完整性异常的资料不能经 PDF 协议读取；
- PDF 页数未知时仍可打开，成功加载后再持久化页数；
- 页码更新必须满足 `1 <= last_page <= page_count`；
- 资料引用只允许 PDF，页码必须为正数且起始页不大于结束页；
- 若已知 PDF 总页数，引用结束页不能越界；
- 删除资料不在 M3 范围内，因此引用使用 `ON DELETE RESTRICT` 保持可追溯性；
- AI 不可用、没有网络或没有 API Key 不影响全部 M3 功能。

## 5. 后续迭代入口

M3 完成后再逐步加入：PDF 文字层提取、图片/PDF OCR、对话上下文选择、引用片段、Token 预估与预算、AI 计划候选版本，以及计划阶段到日程任务的确认式展开。
