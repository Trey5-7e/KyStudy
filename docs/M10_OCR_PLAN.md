# M10：题目区域本地 OCR 实施计划

| 项目     | 内容                                                    |
| -------- | ------------------------------------------------------- |
| 状态     | implemented，已完成人工验收                             |
| Schema   | v13                                                     |
| 目标     | 把已保存的 PDF 题目区域转为可纠正、可确认的本地文字草稿 |
| AI 消耗  | 无；OCR 不调用 Provider，也不消耗云端 Token             |
| 首批平台 | Windows 11 x64                                          |

## 1. 本批次交付

1. 在每道题的“来源区域”下提供独立的本地 OCR 管理；
2. PDF.js 从原 PDF 按归一化坐标重新渲染区域 PNG，输出固定为 1600 像素长边，不依赖当前缩放、旋转、DPR 或窗口大小；
3. Rust 只接受有大小上限和正确 PNG 签名的字节，在内部受控临时目录落盘；
4. 按需启动 TV-07 验证过的 RapidOCR Worker，完成后退出，不常驻；
5. 支持识别中的显式取消和 90 秒超时；
6. 保存逐行文本、置信度和相对于区域图片的归一化文字框；
7. OCR 输出先进入可编辑草稿，只有用户确认后才成为正式确认文本；
8. 重新识别只替换同一区域的旧草稿，不提前覆盖已经确认的文本；
9. 丢弃草稿不会删除旧确认文本、题目区域或原 PDF；
10. 组件缺失、不完整、不兼容、Worker 失败和结果非法均映射为稳定错误，不向 WebView 返回路径、stderr、堆栈或第三方原始错误。

## 2. 处理链路

```text
已保存 QuestionRegion
  -> PDF.js 读取原 PDF 页
  -> 1600 px 长边 PNG 区域
  -> Tauri IPC 字节数组
  -> Rust 受控临时文件
  -> 按需启动本地 OCR Worker
  -> 校验稳定 JSON Schema
  -> SQLite OCR 草稿与文字框
  -> 用户编辑
  -> 确认文本
```

原 PDF 和 `question_region` 始终是事实来源。OCR 文本是附加信息，不能替代题目图片，尤其不能把普通文本识别结果包装成可靠的公式、矩阵或表格语义。

## 3. 组件发现与运行

正式托管目录为 `<app-data>/components/ocr/kystudy-ocr-worker`。当前尚未交付组件下载、安装、更新和移除页面；开发环境会在正式托管目录不存在时检查：

```text
experiments/tv-07-ocr/output/pyinstaller/dist/kystudy-ocr-worker
```

组件必须同时包含 Worker、RapidOCR 三个模型和 ONNX Runtime 核心文件，缺少任一关键文件都显示“不完整”，不会尝试拼接运行。模型随组件提供，识别时不联网下载。

## 4. 并发、取消与资源边界

- 前端每次生成新的 UUID 作为操作标识；
- Rust 协调器全局只允许一个 OCR Worker，并保存对应取消标志；
- 当前界面一次只发起一个区域识别，切换题目也不能绕过后端并发限制；
- Worker 每次识别单独启动，标准输入只传内部临时路径，进程完成后回收；
- Windows 启动时使用无控制台窗口标志；
- 取消或超时会终止 Worker，不保存半成品草稿；
- PNG 最大 12 MiB，Worker 输出最大 2 MiB；
- 最多接受 5000 行、单行 2000 字符和总计 100000 字符；
- 坐标、置信度、引擎名称和 Worker Schema 全部经过 Rust 校验。

## 5. 数据生命周期

一个题目区域最多同时拥有：

- 一份 `draft`：最新 OCR 输出，可编辑、确认或丢弃；
- 一份 `confirmed`：当前用户确认文本；
- 任意数量 `superseded`：过去的确认版本，只保留为历史，不返回当前页面。

确认新草稿时，旧 `confirmed` 在同一事务内转为 `superseded`，新草稿转为 `confirmed`。删除题目区域时，其 OCR 记录和文字框随外键级联删除；删除整道题仍遵循现有回收站与区域生命周期。

## 6. 隐私与 Token

- OCR 默认完全离线，不调用 AI Provider；
- API Key、AI 预算和 AI 调用历史与本流程无关；
- WebView DTO 不包含临时文件路径、组件安装路径、SQL、内部 JSON、stderr 或请求指纹；
- 组件原始错误只映射为稳定错误码和可执行提示；
- 备份包含数据库中的草稿、确认文本和文字框，原 PDF 继续由既有 Blob 备份处理。

## 7. 本批次不包含

- 自动检测整页中的题目边界、题号或答案区域；
- 对整本习题册批量 OCR；
- 图片资料和博主规划图片的 OCR；
- 从图片生成思维导图草案；
- 数学公式结构化识别、手写体识别、自动判题或 AI 错因分析；
- OCR 组件的下载、安装、升级、移除和第三方许可证展示页面；
- macOS、Linux、ARM 或 GPU 推理；
- M9 AI 对话体验优化。

这些能力应在本次真实资料验收后按价值继续迭代，不能以当前区域文字识别冒充完成。
