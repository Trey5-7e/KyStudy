# R38 周期计划管理窗口验收

R38 收敛周期计划卡片和维护入口：卡片只保留一个“查看计划”动作，摘要、编辑和归档统一在同一个 `EditorDialog` 中完成。本文记录实现契约、定向证据和本次完整自动门禁结果；自动门禁已通过，桌面用户验收已通过。页面背景高度的两张截图属于独立后续跟进，不影响 R38 验收结论。

## 1. 用户目标与交互范围

- 在“计划”页快速扫读计划名称、完成率和预计完成日期，点击卡片唯一动作“查看计划”；
- `EditorDialog` 的三个模式为 `summary`、`edit`、`archive`：摘要显示进度、日期、节奏、下一项和月历可见性；编辑保存计划规则；归档先确认；
- 摘要中的编辑规则、月历显示/隐藏、从选中日期后顺延一个学习日和归档均留在该窗口；超期建议进入带初始值的编辑模式；
- 新建周期计划仍使用原有表单和窗口入口。

## 2. 保留边界

本轮只调整计划卡片和窗口呈现，不改变计划数据或排程语义。以下命令和数据继续沿用：

- `get_cycle_plan_dashboard`、`save_cycle_plan`、`set_cycle_plan_item_state`、`shift_cycle_plan`、`archive_cycle_plan`、`refresh_cycle_plan_schedules`；
- 节奏/均匀排程、每周休息日、月历可见性、完成进度、截止日期提示和顺延规则；
- 归档仍从活动列表和月历移除计划，但保留历史进度与学习记录；不新增迁移、不改变 schema、题目/复习数据或已有日程命令。

## 3. 状态、焦点与无障碍契约

- 编辑草稿与初始值比较形成 `dirty`；关闭或从编辑返回摘要时沿用 `EditorDialog` 的“放弃修改/继续编辑”确认，离开页面前也保留未保存提示；
- 保存、切换月历、顺延和归档共享 `busy` 状态：按钮和表单禁用，窗口设置 `aria-busy`，状态通过 `role="status"`/`aria-live` 告知进展；错误继续使用可行动的周期计划错误映射；
- 打开时焦点进入窗口标题（新建表单可指定首个控件），关闭后返回触发卡片按钮，触发器失效时回退到计划列表标题；返回、关闭和归档按钮有可读标签；
- 窗口使用标题/说明关联、语义 `progress`、`dl` 摘要、状态播报和归档 `alert`，不依赖颜色传达进度或危险操作；
- 长名称和说明允许断行；`640px` 以下摘要、可见性和操作改为堆叠，日期摘要改为两列，`320px` 以下改为单列并保持卡片和按钮不溢出。
