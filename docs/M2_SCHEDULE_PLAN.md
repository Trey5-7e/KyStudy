## 1. 目标

M2 要让 KyStudy 第一次成为可以每天使用的学习软件。用户不依赖 AI，也不需要先搭建知识库，就能完成以下闭环：

```text
创建任务 → 在今日查看 → 记录实际学习 → 完成或调整 → 查看当天反馈 → 次日继续
```

M2 完成时，用户应能清楚回答：

- 今天有哪些任务，优先顺序是什么；
- 每项任务预计需要多久，实际投入了多久；
- 哪些任务已经完成、取消、延期或拆分；
- 原计划如何变化，是否存在长期积压；
- 今天计划完成了多少，而不是只看到连续打卡天数。

## 2. 产品边界

### 2.1 M2 实现

- 科目的最小创建、排序和归档能力；
- 按本地日历日期创建手动任务；
- 今日任务列表、快速完成和任务详情；
- 完成、重新打开、延期、取消、恢复和拆分；
- 不可变的关键任务变化记录；
- 手动记录实际学习时长、完成程度和简短复盘；
- 周日程视图与逾期任务入口；
- 今日和本周的最小计划/实际统计；
- M2 数据随现有完整备份一起保存和恢复；
- 全部功能在离线状态可用。

### 2.2 M2 不实现

- AI 自动创建或调整日程；
- AI 规划草案、冲突分析和计划版本；
- PDF 阅读、OCR、题目或错题队列；
- 知识节点与任务关联；
- 精确到分钟的拖拽式时间轴、重复任务和复杂模板；
- 后台计时器、番茄钟、系统通知和日历同步；
- 趋势图、预测模型、连续打卡或社交排名；
- 多工作区切换、云同步和多人协作。

这些功能不需要预留空 Service、插件接口或通用规则引擎。真实需求进入对应里程碑时再扩展。

## 3. 核心产品决定

### 3.1 今日清单优先于复杂日历

“今日”是默认行动入口。M2 先保证创建、查看、完成和调整任务足够快，再实现周视图。首版周视图使用按日期分组的列表，不引入拖拽库。

### 3.2 手动计划是默认路径

M2 的正式任务均由用户手动创建，`source_type` 固定为 `manual`。未来 AI 只能生成候选任务，用户确认后才能以 `ai_confirmed` 写入同一正式模型。

### 3.3 日期与时间分开

- 任务计划日期保存为 `YYYY-MM-DD`，按工作区时区解释；
- M2 不要求任务必须设置具体开始时间；
- 创建、修改和完成时间保存为 UTC 毫秒时间戳；
- 预计时长和实际时长分开保存，互不覆盖；
- 前端可以发送正在查看的日期，但 Rust 必须重新校验格式和范围。

这样可以避免在首版引入夏令时、跨时区拖拽和分钟级冲突等不必要复杂度。

### 3.4 科目允许稍后补充

任务可以暂时不选科目，界面显示“未分类”。这保证用户第一次打开今日页时可以立即记录任务。科目归档后，历史任务仍保留关联和显示名称，不级联删除任务。

### 3.5 完成和学习记录分离

任务状态回答“这件事是否结束”；学习记录回答“实际投入了多少”。

- 任务可以完成但不填写实际时长；
- 一项任务可以有多条学习记录；
- 新增学习记录不会修改预计时长；
- 重新打开已完成任务不会删除已有学习记录；
- 基础统计分别展示计划分钟和实际分钟。

## 4. 状态与业务规则

### 4.1 任务状态

| 当前状态               | 允许操作 | 结果                        |
| ---------------------- | -------- | --------------------------- |
| `todo`                 | 开始     | `in_progress`               |
| `todo` / `in_progress` | 完成     | `done`，写入 `completed_at` |
| `todo` / `in_progress` | 取消     | `canceled`                  |
| `done`                 | 重新打开 | `todo`，清空 `completed_at` |
| `canceled`             | 恢复     | `todo`                      |

延期只改变 `planned_date`，不自动改变状态。已完成或已取消任务必须先重新打开/恢复，之后才能延期。

### 4.2 排序

今日列表默认按以下顺序稳定排序：

1. `in_progress` 在 `todo` 之前；
2. 高优先级在普通、低优先级之前；
3. 有手动排序值时按手动排序；
4. 最后按创建时间和 ID 排序。

首版不让 AI 参与排序。用户调整的顺序必须可持久化，不能因重启改变。

### 4.3 延期

- 新日期必须是合法本地日历日期；
- 新旧日期相同时不产生变化记录；
- 每次延期在同一事务中更新任务并插入 `task_change`；
- 历史至少保留原日期、新日期、原因和发生时间；
- 逾期任务不会被后台自动延期，必须由用户决定。

### 4.4 拆分

用户将一个未完成任务拆成至少两个子任务：

- 父任务与所有子任务在一个事务中写入；
- 子任务保存 `parent_task_id`，默认继承科目、日期和优先级；
- 用户为每个子任务填写标题和可选预计时长；
- 父任务进入 `canceled`，变化类型为 `split`；
- 任一步失败时不留下半个拆分结果。

### 4.5 删除

M2 不把“删除”当作日常任务状态。误建任务可以进入回收站，通过 `deleted_at` 隐藏，并支持恢复。清空回收站和硬删除进入后续数据维护功能。

## 5. 数据模型

M2 从 schema v3 开始，只进行新增表和新增可空字段，不删除或重写 M1 数据，因此不属于高风险迁移。后续工作项只有在对应表开始被正式用例使用时才增加后续 schema 版本，不提前创建空表。

### 5.1 `subject`

| 字段                        | 约束                        |
| --------------------------- | --------------------------- |
| `id`                        | UUIDv7 文本主键             |
| `workspace_id`              | 外键，不为空                |
| `name`                      | 去除首尾空格后 1～40 个字符 |
| `color_key`                 | 受控语义颜色键，不保存 CSS  |
| `sort_order`                | 非负整数                    |
| `archived_at`               | 可空 UTC 毫秒时间戳         |
| `created_at` / `updated_at` | UTC 毫秒时间戳              |

同一工作区内，未归档科目名称按规范化结果唯一。M2 不删除科目。

### 5.2 `task`

| 字段                        | 约束                                      |
| --------------------------- | ----------------------------------------- |
| `id`                        | UUIDv7 文本主键                           |
| `workspace_id`              | 外键，不为空                              |
| `subject_id`                | 可空外键                                  |
| `parent_task_id`            | 拆分来源，可空自引用外键                  |
| `title`                     | 去除首尾空格后 1～120 个字符              |
| `description`               | 可空，最多 2,000 个字符                   |
| `planned_date`              | 严格 `YYYY-MM-DD`                         |
| `estimated_minutes`         | 可空，1～1,440                            |
| `priority`                  | `low`、`normal`、`high`                   |
| `status`                    | `todo`、`in_progress`、`done`、`canceled` |
| `manual_order`              | 非负整数                                  |
| `source_type`               | M2 固定 `manual`                          |
| `completed_at`              | 仅 `done` 时非空                          |
| `deleted_at`                | 可空 UTC 毫秒时间戳                       |
| `created_at` / `updated_at` | UTC 毫秒时间戳                            |

主要索引：

- `task(workspace_id, planned_date, status, deleted_at)`；
- `task(workspace_id, subject_id, planned_date)`；
- `task(parent_task_id)`。

### 5.3 `task_change`

| 字段                         | 约束                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `id`                         | UUIDv7 文本主键                                                                                                    |
| `task_id`                    | 外键，不为空                                                                                                       |
| `change_type`                | `created`、`edited`、`rescheduled`、`started`、`completed`、`reopened`、`canceled`、`restored`、`split`、`trashed` |
| `before_json` / `after_json` | 只保存允许审计的任务字段快照                                                                                       |
| `reason`                     | 可空，最多 500 个字符                                                                                              |
| `created_at`                 | UTC 毫秒时间戳                                                                                                     |

快照不得包含路径、SQL、内部错误、密钥或未来 AI Prompt。记录一经创建不原地修改。

### 5.4 `study_session`

该表在 M2-007 实际学习记录用例落地时通过后续迁移创建，不包含在 M2-002 的 schema v3 中。

| 字段                        | 约束                    |
| --------------------------- | ----------------------- |
| `id`                        | UUIDv7 文本主键         |
| `workspace_id`              | 外键，不为空            |
| `task_id`                   | 可空外键                |
| `subject_id`                | 可空外键，记录当时科目  |
| `session_date`              | 严格 `YYYY-MM-DD`       |
| `duration_minutes`          | 1～1,440                |
| `completion_percent`        | 0～100 的整数           |
| `reflection`                | 可空，最多 2,000 个字符 |
| `created_at` / `updated_at` | UTC 毫秒时间戳          |
| `deleted_at`                | 可空 UTC 毫秒时间戳     |

M2 先支持手动记录有效分钟数，不实现后台计时器。统计只计算未进入回收站的记录。

## 6. Rust 用例与 Command 边界

Command 只接收业务 DTO，不接收 SQL、绝对路径、任意 JSON 查询或前端生成的数据库 ID。

建议的最小 Command：

| Command                   | 用途                                   |
| ------------------------- | -------------------------------------- |
| `list_subjects`           | 返回当前工作区科目                     |
| `create_subject`          | 创建科目                               |
| `archive_subject`         | 归档科目                               |
| `list_tasks_for_range`    | 查询闭区间日期范围内的任务             |
| `create_task`             | 创建手动任务                           |
| `update_task_details`     | 修改标题、说明、科目、预计时长和优先级 |
| `transition_task`         | 执行受控状态迁移                       |
| `reschedule_task`         | 延期并记录历史                         |
| `split_task`              | 原子拆分任务                           |
| `trash_task`              | 软删除任务                             |
| `list_trashed_tasks`      | 查询回收站任务                         |
| `restore_trashed_task`    | 恢复误删任务                           |
| `list_overdue_tasks`      | 查询显式日期之前的未完成任务           |
| `list_task_changes`       | 查看单个任务变化历史                   |
| `create_study_session`    | 新增实际学习记录                       |
| `list_study_sessions`     | 查询任务或日期范围的记录               |
| `get_study_statistics`    | 返回确定性的基础统计                   |

前端 DTO 不返回 SQLite 行号、数据库路径或 JSON 快照原文。变化历史由 Rust 转换为明确字段后返回。

## 7. 页面与交互

### 7.1 应用导航

M2 开始建立正式主导航，但只启用当前可用页面：

- 今日；
- 日程；
- 资料库；
- 设置/工作区。

未实现的规划室、导图、习题册、错题和 AI 不显示可点击空页面。

### 7.2 今日页

今日页第一版包含：

- 当前日期与可切换日期；
- 完成数量、计划分钟、实际分钟；
- 按状态和优先级排序的任务列表；
- 快速新建任务；
- 开始、完成、延期和打开详情；
- 逾期任务数量及入口；
- 没有任务时的明确空状态。

完成操作可以直接执行；若用户希望记录实际时长，则在同一流程中展开可选表单。不能强迫用户为了勾选完成填写复盘。

### 7.3 任务详情

使用右侧详情面板统一承载：

- 标题、说明、日期、科目、预计时长和优先级；
- 当前状态与可执行动作；
- 实际学习记录；
- 延期、取消、拆分和回收站操作；
- 只读变化历史。

关闭详情面板不能丢失已经明确提交的数据；未保存编辑需要提示。

### 7.4 日程页

首版周视图显示连续 7 天，每天一列或一组。普通笔记本宽度不足时改为横向滚动或按天分组，不能压缩到不可读。

- 支持上一周、下一周和回到今天；
- 支持按科目筛选；
- 显示每天计划分钟和完成数量；
- 逾期任务单独显示，不静默塞进今天；
- 调整日期使用明确操作，不在首版实现拖拽。

### 7.5 基础统计

只显示可直接解释的数字：

- 正式任务数、已完成数和完成率；
- 计划分钟、实际分钟及差值；
- 逾期未完成任务数；
- 按科目汇总的任务数和实际分钟。

取消和回收站任务不进入完成率分母。没有任务时显示“暂无数据”，不显示误导性的 100%。

## 8. 测试策略

### 8.1 Domain

- 标题、日期、时长和优先级校验；
- 所有允许和拒绝的状态迁移；
- 今日稳定排序；
- 完成率、计划分钟和实际分钟计算；
- 逾期判定不依赖系统当前时间，测试显式传入日期。

### 8.2 Application

- 创建任务同时写入 `created` 历史；
- 延期同时更新日期和写入历史；
- 拆分全部成功或全部回滚；
- 完成与学习记录可以在同一用户动作中原子写入；
- 归档科目不会删除任务；
- 不存在工作区时返回稳定错误。

### 8.3 SQLite

- schema v2/v3 原地升级到 v4；
- 外键、CHECK、唯一约束和索引实际生效；
- 日期范围查询顺序稳定；
- 事务失败不留下半条历史或半个拆分；
- 备份恢复后任务、历史和学习记录一致。

### 8.4 Command 与前端

- DTO 解析拒绝缺字段、非法枚举和超范围数值；
- 任意后端错误文本不直接显示；
- DTO 不包含路径、SQL、内部 JSON 快照或数据库字段；
- 空状态、加载、失败、完成、逾期和归档科目状态均有测试；
- 核心按钮支持键盘，状态不只依赖颜色表达。
