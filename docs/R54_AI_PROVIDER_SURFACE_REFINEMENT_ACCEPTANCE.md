# R54 AI Provider 管理界面收敛批次

## 批次结论

R54 收敛 AI Provider 管理窗口的首屏操作。Provider 卡片默认只展示状态、模型、目的地，以及“设为当前/测试连接”等主路径；编辑和删除动作移入每张卡片的“更多操作”折叠区。Provider 编辑表单中的上下文上限和单次最大输出继续默认折叠。

本批次只调整前端信息层级，不改变 Provider、API Key、预算、连接测试、调用历史或后端命令契约。API Key 仍只写入 Windows 凭据管理器，用户没有展开高级区域时不会增加任何外发行为。

## 实现范围

- `src/features/ai/AiFoundationPanel.tsx`
  - 保留“设为当前”和当前 Provider 的“测试连接”为卡片主动作；
  - 新增可键盘操作的“更多操作”`details`，收纳“编辑”和删除二次确认；
  - 不改变编辑、删除、切换 Provider 和密钥清理的状态流转。
- `src/features/ai/ai.css`
  - 为折叠入口和展开菜单增加紧凑样式、焦点可见性继承和窄屏定位；
  - 不引入新的组件库或运行时依赖。

### 验收反馈修复

首轮桌面检查发现，第一张 Provider 卡片的“更多操作”展开区会被后续卡片遮挡。原因是 Provider 列表项上的 `content-visibility: auto` 形成了溢出隔离。R54 已移除这项不必要的列表隔离，并为展开项提升层级、限制窄窗口宽度；Provider 列表最多 20 项，不需要依赖该渲染优化。

## 桌面验收清单

用户使用最新 Release 构建启动应用后，在“设置 → AI”执行：

1. 确认当前 Provider 卡片仍显示当前名称、模型、目的地、密钥状态和 Token 摘要。
2. 点击“管理 AI 配置”，确认 Provider 卡片默认只突出“设为当前/测试连接”；每张卡片出现“更多操作”。
3. 展开“更多操作”，确认“编辑”和“删除”出现；关闭后再次打开，确认操作状态不会串到其他 Provider。
4. 通过“编辑”修改显示名称并保存，确认卡片更新；通过“删除”执行二次确认，确认取消和确认删除的行为与 R9 一致。
5. 新增或编辑 Responses API Provider，确认 API Key 输入、保存、删除密钥仍可用，且不会回显已保存密钥。
6. 进入“连接测试”、Token 预算和调用历史，确认原有预览、预算阻止/警告和脱敏历史仍可用。
7. 在窄窗口中重复第 2～4 步，确认“更多操作”菜单不会遮挡 Provider 名称，且键盘可以展开、聚焦并触发按钮。

本清单只要求记录界面稳定提示和不含隐私的截图，不要展示 API Key、完整测试文本、数据库、路径或 Provider 原始错误。桌面验收由项目维护者执行；本文件不宣称桌面验收已通过。
