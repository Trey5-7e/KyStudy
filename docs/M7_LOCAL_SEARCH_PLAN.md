# M7：本地 PDF 文字索引与可追溯搜索

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 状态     | ready-for-acceptance                                         |
| 前置条件 | M6 综合验收已通过                                            |
| 目标     | 在不接 AI、不做 OCR 的前提下建立本地解析、检索和页码引用底座 |

## 1. 本批次交付

1. 使用现有 PDF.js 受控 Range 阅读链路逐页提取 PDF 文字层；
2. schema v9 保存页面文字状态、确定性文本片段、内容哈希和可重建 FTS5 索引；
3. 每份 PDF 显示未索引、处理中、中断、失败、可搜索或无文字层状态；
4. 索引任务可取消、继续和强制重建，应用异常退出后不会永久停留在处理中；
5. 文件内容与页数未变化时不重复解析；
6. 全文搜索返回资料名称、页码、有限摘要和匹配类型，可直接跳转原 PDF 页面；
7. 一到两个字符使用有界页面文本匹配，较长查询使用 FTS5 trigram；
8. 索引、页面文字和片段均为本地派生数据，不向前端暴露路径、SQL、存储键或内部错误；
9. 旧工作区和旧备份自动迁移到 v9，正式资料、题目、错题和复习历史保持不变；
10. 完整备份与跨目录恢复覆盖 schema v9，索引也可以从原始 PDF 重新生成。

## 2. 明确边界

- 本批次不接 AI Provider、API Key、对话、摘要、向量索引或 Token 预算；
- 不自动上传、外发或同步任何页面文字；
- 扫描页和纯图片 PDF 只标记为“无文字层”，不自动启动 OCR；
- 不在后台无提示地解析全部资料，必须由用户主动开始；
- PDF.js 只读取已有受控 document ID，不获得文件路径；
- 搜索结果只显示有限摘要，不把整页内容作为列表 DTO 返回；
- FTS 表属于派生数据，不能成为题目、任务或知识节点的正式数据来源。

## 3. 后续连接

M8 将以 M7 的页面与片段为唯一资料上下文入口，在外部调用前展示将发送的文件、页码、片段和 Token 预估。若 M7 的全文搜索不能满足真实规划问答，再评估本地向量索引，而不是提前引入。
