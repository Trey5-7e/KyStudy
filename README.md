# KyStudy

> 一个为中国考研人设计的、本地优先的学习资料、规划与错题复习软件。

KyStudy 希望把备考中容易被忽略的环节交给软件：如何从众多经验中形成适合自己的计划、今天该学什么、学习是否按计划推进、哪些错题该复习。它不替用户决定目标，也不把连续打卡当作学习效果；它的职责是让资料、计划、执行、练习和复习形成可追踪的闭环。

> M1 本地基础已经完成：工作区、资料导入、完整备份、Windows CI 和离线启动均已通过验收。项目正在规划 M2 日程闭环；PDF 阅读、错题与 AI 尚未进入正式实现。

## 当前工程

正式工程位于仓库根目录，实验仍保留在 `experiments/` 中且不会直接并入业务代码。当前已经具备：

- React 19 + TypeScript 6 + Vite 8 的严格前端构建；
- Tauri 2 + Rust 1.97 的最小桌面运行时；
- 只返回非敏感运行信息的类型化 `get_runtime_status` Command；
- 前端 DTO 运行时校验与稳定错误映射；
- 用户触发的默认工作区创建、SQLite v3 迁移与重启恢复；
- 按工作区时区显示的今日任务、快速新建、优先级排序、完成与重新打开；
- 任务创建和状态变化的事务化不可变历史；
- Rust 原生文件选择、固定内存流式导入、SHA-256 物理去重、取消和中断恢复；
- 不暴露文件路径的资料列表、导入进度和稳定错误界面；
- 版本化完整备份、SQLite 一致快照、Blob 校验和跨目录恢复副本；
- 锁定 Rust 工具链、Windows CI、隔离 Release 启动 Smoke 和可下载验证产物；
- pnpm/Cargo 锁文件，以及格式、Lint、类型、测试、Clippy 和 Release 构建门槛。

常用验证命令：

```powershell
pnpm install --frozen-lockfile
```

## 面向谁

- 准备全国硕士研究生招生考试、尤其需要长期管理多门科目的人；
- 希望在自己的电脑上保存备考资料、学习记录、错题和笔记的人；
- 希望有辅助分析，但保留自己对学习计划最终决定权的人。

首个版本以单人、本地使用为目标。未来可以扩展同步和协作，但不会将其作为使用 KyStudy 的前提。

## 想解决的问题

备考中的常见问题不是“没有任务”，而是：

1. 每天的任务很多，却不清楚优先做什么，也不知道计划是否现实；
2. 习题、错题、笔记散落在书本、相册和不同应用中，难以回顾；
3. 错题复习依赖记忆，容易漏掉该复习的内容；
4. 学习时长、完成率和正确率彼此割裂，难以定位真正的薄弱点。
5. 网络上的备考经验很多，但直接照搬通常不适合自己的基础、进度和时间安排。

KyStudy 的核心闭环是：**导入资料 → 形成个人规划 → 记录执行 → 管理知识与练习 → 自动安排错题复习 → 查看进展 → 调整计划**。

## 核心功能

### 1. 每日日程与待办清单

用户可以按日期创建学习任务，并设置科目、知识点、预计时长、优先级和完成状态。

- 今日视图集中显示当天任务、今日错题复习和已完成情况；
- 任务可延期、拆分、标记未完成，并保留真实执行记录；
- 可配置固定可学习时段和考试日期，帮助判断计划是否过满；
- AI 可以基于学习情况**生成建议计划**，但默认不自动创建、删除或调整任何任务；用户确认后才会写入日程。

### 2. 学习资料与 AI 规划对话

用户可以导入博主分享的备考规划、经验文章、课程安排等图片和 PDF，并围绕这些资料与 AI 对话，逐步形成适合自己的学习规划。

- 支持本地保存图片与 PDF，按科目、来源和用途分类；
- 文字型 PDF 优先直接提取文本，扫描件和图片按需进行 OCR；
- AI 回答应标注所依据的文件、页码或图片，方便用户核对原文；
- 可以比较多份规划，提取共同阶段、时间安排、前置条件和可能冲突；
- AI 会结合考试日期、当前基础、每天可用时间、实际进度和用户偏好生成规划草案；
- 规划保留版本历史，AI 的修改以差异或候选方案呈现，用户确认后才进入日程。

对话不会在每次请求中重新发送全部资料。KyStudy 会先在本地解析和索引文件，只取与当前问题有关的片段作为上下文。

### 3. 思维导图与知识结构

知识库的第一种形态是可编辑的思维导图。它用于建立科目、章节与知识点之间的结构，并成为任务、资料、题目和错题的共同索引。

- 支持从空白导图开始创建、拖拽、增删、合并和调整节点；
- 支持导入常见的结构化思维导图或大纲格式，具体格式将在技术验证后确定；
- 对于思维导图图片或 PDF，可由 AI 识别为一份可编辑的导图草案，再由用户校对；
- 每个节点可关联学习任务、资料页码、题目、错题和个人笔记；
- 支持记录掌握状态、最后学习时间和薄弱程度；
- AI 可以建议补充、拆分或重组节点，但不能在未经确认时覆盖用户导图；
- 后续可在思维导图基础上扩展 Markdown 笔记、知识图谱和语义检索。

导入需要区分两种情况：结构化思维导图可以尽量保留层级与节点；普通图片只能通过识别生成草案，无法保证与原图一比一还原。

### 4. PDF 习题册与题目管理

用户可以把自己有权使用的练习册 PDF 导入本地资料库。KyStudy 以 PDF 页面和区域为基础管理题目，不要求用户重新誊写整道题。

- 提供 PDF 阅读、缩略图、书签、批注和学习进度；
- 识别目录、章节、题目区域和答案区域，并生成待确认的结构化结果；
- 用户可在 PDF 页面上框选一道题，将该区域直接创建为题目；
- AI 可建议知识点、题型、难度和错误原因，也可把题目关联到思维导图节点；
- 用户可以查看题目的原始页面、历次作答、错题记录、答案与个人解析；
- 扫描版 PDF 使用本地或按需 OCR，文本型 PDF 则直接利用其文字层；
- AI 识别结果始终允许人工纠正，原始 PDF 保持不变。

每道题至少可记录：

- PDF 来源、页码和页面区域，必要时补充章节或题号；
- 题目截图、识别文本和本地附件；
- 关联的知识点与难度；
- 每次作答的日期、结果、耗时、答案/笔记；
- 错误原因，例如知识遗漏、概念混淆、计算失误、审题问题或时间策略问题。

完整 PDF、题目截图和识别结果默认只保存在用户设备，不随开源项目发布，也不会在未提示用户时发送给第三方 AI 服务。

### 5. 错题本与每日复习队列

用户可设置每天希望复习的错题数量，例如 5 道。系统每天从待复习错题中生成固定数量的队列，并按优先级排序。

建议的初始优先级因素：

1. 是否已逾期；
2. 距上次复习的时间；
3. 历史错误次数与连续未掌握次数；
4. 用户标记的重要程度；
5. 所属知识点的薄弱程度。

完成复习后，用户只需标记“掌握 / 不确定 / 未掌握”。系统据此安排下一次复习时间；重复出错的题会更早再次出现。首版采用透明、可解释的间隔复习规则，之后再评估是否引入更复杂的记忆模型。

每日数量代表用户希望完成的复习配额。系统仍会显示已逾期数量和预计清空时间，避免固定的“每天 5 道”掩盖不断增长的错题积压。

### 6. AI 与 Token 消耗控制

Token 成本是 KyStudy 的核心设计约束。AI 功能应提供可见、可控的消耗，而不是把整份资料和全部聊天记录反复提交给模型。

- **本地预处理**：PDF 解析、OCR、全文搜索、文件哈希和基础统计尽量在本地完成；
- **按需检索**：只向模型发送与当前问题相关的章节、页面或题目片段；
- **增量索引**：同一文件未发生变化时不重复解析和索引；
- **分层摘要**：保存文档、章节和对话摘要，需要时逐层展开，而不是携带完整历史；
- **结构化记忆**：把考试日期、可用时间、科目进度和偏好保存为字段，不依赖模型从长对话中反复提取；
- **模型分工**：分类、提取和标签任务使用成本较低的模型，复杂规划与题目分析再使用能力更强的模型；
- **结果缓存**：相同文件片段和相同任务可以复用已有结果；
- **预算控制**：支持单次预估、每日/月度上限、用量统计和超限提醒；
- **用户触发**：大批量 OCR、整本习题册分析和重新索引必须由用户主动发起。

后续可增加本地嵌入模型、本地 OCR 甚至本地大模型，使更多处理无需消耗云端 Token。

## 产品原则

- **本地优先**：学习数据、题目图片和笔记默认保存在用户设备；提供导出和备份。
- **用户拥有最终控制权**：AI 的输出只能是建议，任何日程或数据修改都需要用户确认。
- **引用可追溯**：基于资料生成的回答应尽可能指向原文件和页码，避免无法核实的结论。
- **成本可见且可控**：调用前可预估，调用后可统计，用户能够设置明确的 Token 预算。
- **低录入负担**：日常记录应在几分钟内完成；宁可字段可选，也不让软件成为额外作业。
- **真实反馈优先于打卡**：重点展示完成率、实际投入、正确率和待复习量，不以连续天数制造压力。
- **尊重版权与隐私**：开源仓库不收录受版权保护的完整题库或个人学习数据。

## 初步使用流程

1. 设置考试日期、科目、固定时间、AI 预算和每日错题复习数量；
2. 上传备考经验图片或 PDF，与 AI 对话并确认一版个人学习规划；
3. 导入或创建知识思维导图，将规划任务关联到相应知识节点；
4. 导入练习册 PDF，在阅读和做题过程中标记题目及错题；
5. 在“今日复习”中完成系统按优先级选出的错题；
6. 每周查看任务完成率、知识点正确率和积压复习量，并据此调整规划。

## 技术方向（暂定）

KyStudy 最终会以桌面软件形态运行，优先考虑跨平台与本地数据控制：

- 桌面壳：Tauri；
- 界面：React + TypeScript；
- 本地数据：SQLite；
- 图片、PDF 与附件：应用数据目录中的本地文件；
- PDF 阅读与区域标注：基于成熟的 PDF 渲染引擎；
- 思维导图：使用结构化节点数据保存，导入和导出由格式适配器负责；
- 本地检索：全文索引优先，按需要增加本地向量索引；
- AI：通过可替换的 API 适配层接入，密钥由用户本地配置，不提交到仓库；
- AI 上下文：采用“本地解析 → 索引 → 检索相关片段 → 调用模型”的流程。

不在首版引入账号体系、云端同步、微服务或社交排行榜。若以后确实需要多设备同步，再以端到端加密、显式授权和可选自托管为前提进行设计。
