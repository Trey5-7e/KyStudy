## 已修复的首次真实 Release 失败

首次人工测试中，窗口能够正常启动，但点击“加载 PDF 实验”后显示“加载失败：Error”。原因是 Tauri `convertFileSrc` 会编码传入的整个值：旧值 `/document/tv04-mixed-document` 在 Windows WebView 中形成了 `/%2Fdocument%2Ftv04-mixed-document` 请求，而 Rust 协议只接受 `/document/...`，所以首个 Range 请求返回 `404`。

修复版只把不透明 `document_id` 交给 `convertFileSrc`，请求 URL 为 `http://kystudy-pdf.localhost/tv04-mixed-document`；Rust 协议也只接受根路径下的 document ID。失败诊断已改为稳定错误码，不再只显示笼统的 `Error`，也不会显示任意异常消息。

## 验收步骤

### 1. 启动与首屏边界

1. 关闭旧窗口后，双击 `tv-04-pdf-viewer.exe`；
2. 等待窗口出现，标题应为“KyStudy TV-04 PDF 技术实验”；
3. 页面应显示“PDF 范围加载与区域坐标实验”；
4. 顶部应显示 `协议修订：direct-id-v2`；
5. PDF 尚未出现，页面应提示“当前未加载 PDF.js”。

通过条件：窗口不是白屏/黑屏，没有闪退，首屏文字和“加载 PDF 实验”按钮完整可见。

### 2. 自定义协议、Worker 与 CSP

1. 点击“加载 PDF 实验”；
2. 状态先显示“正在按范围加载 PDF…”，随后变为“第 1/6 页”；
3. 第一页应出现 PDF Canvas，可看到英文标题、中文“计算机考研”和红色 `REGION-0` 区域。

通过条件：没有出现“加载失败”或“渲染失败”。这一步同时证明 Release WebView 中的 Rust 自定义协议、PDF.js Worker 和 CSP 能共同工作。

### 3. 翻页与无文字层降级

1. 连续点击“下一页”，检查页码依次到第 6/6 页；
2. 前四页的方向应不同，第五页是双栏/公式占位内容；
3. 第六页是没有文字层的灰色扫描模拟页，但仍应正常显示；
4. 第六页时“下一页”按钮应禁用；
5. 点击“上一页”回到第 1 页。

通过条件：各页均能显示，按钮边界正确，第六页不会因为没有文字层而打不开。

### 4. 框选、旋转与缩放

1. 在第 1 页 PDF 上拖动鼠标，尽量框住红色 `REGION-0` 区域；
2. 松开后应出现半透明红色覆盖框，状态栏显示四个 0–1 坐标；
3. 点击“旋转”，页面宽高应交换，红色覆盖框仍应覆盖同一块 PDF 内容；
4. 再点击“放大”两次和“缩小”一次，覆盖框仍应跟随原内容；
5. 最大化窗口再恢复，覆盖框不应漂移到其他题目。

通过条件：覆盖框在旋转、缩放和窗口变化后仍对应原 PDF 内容，不按原屏幕像素停留。

### 5. 重启恢复与清除

1. 保留刚才的框选，关闭整个应用；
2. 再次双击 EXE，点击“加载 PDF 实验”；
3. 第 1 页渲染完成后，先前的覆盖框应自动恢复；
4. 点击“清除框选”，覆盖框应消失，状态显示“已清除实验框选”；
5. 再关闭并重新打开应用、加载 PDF，覆盖框不应再次出现。

通过条件：版本化的最小坐标数据可以跨应用重启恢复，清除后不会复活。实验使用 localStorage 验证序列化；正式工程会改由 SQLite 保存。

### 6. 快速操作与关闭

1. 快速交替点击“下一页”和“上一页”约 10 次；
2. 再连续点击“旋转”和“放大”；
3. 页面最终应停在一个完整清晰的页面，不出现两个页面重叠、永久空白或按钮卡死；
4. 正常关闭窗口。

通过条件：旧 RenderTask 能被取消，窗口正常关闭，无崩溃提示。
